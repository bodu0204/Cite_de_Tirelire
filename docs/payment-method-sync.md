# 支払い方法と手元のお金の照合（現金・口座・電子マネー・クレカ） As-Is / To-Be

作成日：2026-11-05（案A「実際の額を純額で入力」＋案B「支出の支払い方法とカードの未払いの目安」）
関係：[record-input-redesign.md](record-input-redesign.md) §6・§8・§9.3、[requirements.md](requirements.md) 3.3・SCR-02・SCR-06・SCR-10、[adjustments.ts](../src/server/adjustments.ts) `estimateItems` / `quoteAdjustment` / `recordAdjustment` / `purchaseBase`、[AdjustTab.tsx](../src/components/records/AdjustTab.tsx)、[ExpenseTab.tsx](../src/components/records/ExpenseTab.tsx)、[schema.prisma](../prisma/schema.prisma) `Purchase` / `Subscription` / `CashAdjustment`

## 1. 目的

支払いの手段によって、**お金が実際に減る時期**が変わる。

| 手段 | 使った時 | あとで |
|---|---|---|
| 現金・デビット | 財布・口座から減る | なし |
| クレジットカード | 減らない（未払いが増える） | 引き落とし日に口座から減る |
| 電子マネー・プリペイド | 減らない（チャージ済みの残高から減る） | — （チャージした時に口座から減っている） |

アプリは支出を**記録した時点で手元のお金が減った**として推測する（[record-input-redesign.md](record-input-redesign.md) §8）。そのため、カードで払ってから引き落とされるまで、口座残高をそのまま「実際の額」として入れると、未払いの分だけ＋の誤差が出る。本書は、支払い方法によらずアプリの表示と現実の所持が合うようにする。

- **案A**：誤差調整の「実際の額」を、お金の置き場所ごとの**純額**（現金 ＋ 口座 ＋ 電子マネー − カードの未払い）で入力する。
- **案B**：支出に**支払い方法**を付け、カードの締め日・引き落とし日から**未払いの目安**を出して、案Aのカードの行の確認に使う。

## 2. 前提と用語

### 2.1 前提

| # | 前提 |
|---|---|
| G1 | **支出は使った日に記録する（発生主義）。** カードでも現金でも同じ。精算・報酬・手数料・貯金額などゲームの判定は**支払い方法によって変えない**（節約の手応えが引き落とし日まで遅れないように） |
| G2 | **カードの引き落とし・電子マネーのチャージは支出として記録しない。** お金の置き場所が変わるだけで、増えも減りもしない（記録すると二重に引くことになる） |
| G3 | 手元のお金の推測（E1〜E6）の意味は変えない。カードの未払いは**現実側の負債**なので、「実際の額」の側で引く |
| G4 | 案Bの目安は**確認用**。正しい値はカード会社の画面の「ご利用額（未確定分を含む）」で、目安と比べることで記録漏れをカード単位で見つけられるようにする |

### 2.2 用語

| 用語 | 定義 |
|---|---|
| 置き場所 | お金がある場所・支払いの手段。種類は 現金・口座・電子マネー・クレカ（`MoneyAccount`） |
| 純額 | 置き場所の額を、現金・口座・電子マネーは＋、クレカは−で足したもの。案Aの「実際の額」 |
| カードの未払い | そのカードで使って、まだ口座から引き落とされていない額（分割・リボの残りも含む） |
| 締め日・引き落とし日 | カードの利用を区切る日と、その分が引き落とされる日（例：15日締め・翌月10日払い） |
| 未払いの目安 | 支払い方法がそのカードの支出のうち、引き落とし日がまだ来ていないものの合計（§5.3） |

## 3. As-Is（現状）

- 誤差調整（SCR-02）の「実際の手元の額」は**1つの入力欄**。ヒントは「財布や口座で確かめた、自由予算の手元のお金」で、カードの未払いを引くかどうかの案内がない（[AdjustTab.tsx](../src/components/records/AdjustTab.tsx)）。
- `CashAdjustment` は `actual`（合計）だけを持ち、内訳は残らない。
- 支出（`Purchase`）・サブスク（`Subscription`）に支払い方法がない。
- 引き落としやチャージを支出として記録しないよう案内する表示がない。

| # | 問題 |
|---|---|
| P1 | カードで払ってから引き落とされるまで、口座残高をそのまま入れると未払い分の＋誤差が出る。解消すると債券が増え、引き落とし後に−誤差になって手数料を払う（行って戻るだけで損をする） |
| P2 | 引き落とし日に請求額を支出として記録すると、二重に引かれる |
| P3 | 誤差が出たとき、どの置き場所のずれか（記録漏れか、カードの未払いを引き忘れたか）がわからない |
| P4 | 前回どう数えたかが残らず、毎回数え方がぶれる |

## 4. To-Be：案A 実際の額を置き場所ごとの純額で入力

### 4.1 置き場所の登録

| ID | 要件 |
|---|---|
| AC-01 | 設定（SCR-10）に「お金の置き場所」を追加する。名前・種類（現金 / 口座 / 電子マネー / クレカ）・並び順を登録できる |
| AC-02 | 置き場所ごとに「実際の額に含める」を持つ（初期値は含める）。貯金用の別口座など、自由予算と関係のない口座は外せる（貯金管理の E5 と組み合わせる） |
| AC-03 | クレカには締め日・引き落とし日・何か月後に払うかを設定できる（任意。案Bの目安に使う。§5.2） |
| AC-04 | 支出や誤差調整で使った置き場所は削除せず、**使わない**にする（履歴の名前を残すため）。使っていない置き場所は削除できる |
| AC-05 | 置き場所を1件も登録していない人は、今の入力欄（合計を1つ入れる）のまま使える。誤差調整の画面から「内訳で入力する」を選ぶと、「現金」「口座」の2件を作って内訳入力に切り替える |

### 4.2 誤差調整での入力

| ID | 要件 |
|---|---|
| AA-01 | 「実際の手元の額」を、含める置き場所ごとの行で入力する。現金・口座・電子マネーは＋、クレカは「未払い」として−で数え、**実際の額 ＝ 純額**を自動で計算して表示する |
| AA-02 | 各行のヒント：現金「財布の中」、口座「アプリ・ATMの残高」、電子マネー「アプリの残高」、クレカ「カード会社の画面の“ご利用額”。未確定分・分割やリボの残りを含める」 |
| AA-03 | 入力欄の初期値は空で、前回の誤差調整の額をプレースホルダーに薄く出す（古い額のまま保存して誤差が隠れないように）。「前回と同じ」ボタンで行ごとに写せる |
| AA-04 | 行を空のまま保存することはできない（0円なら0を入れる）。数えない置き場所は「実際の額に含める」を外す |
| AA-05 | 合計を直接入れる欄・誤差を直接 ＋／− で入れる欄（ADJ-04）は「合計で入力」に切り替えて残す |
| AA-06 | 画面の下に注意書きを出す：「カードの引き落とし・電子マネーのチャージは支出として記録しないでください（置き場所が変わるだけです）」 |
| AA-07 | 保存すると、置き場所ごとの名前・種類・額を `CashAdjustment.accounts` に残す（ADJ-07 に追加）。履歴では内訳を開いて見られる |
| AA-08 | グラフ（§8.3）の「実際の額」の縦線は純額に引く。表示は今と同じ（内訳はグラフにしない） |
| AA-09 | 誤差の解消（ADJ-05）・報酬なし（ADJ-08）・保存後に編集しない（ADJ-09）は今と同じ |

> 例：現金 8,000円・口座 152,000円・電子マネー 3,000円・カード未払い 41,000円 → 実際の額 122,000円。推測が 120,500円なら誤差 +1,500円。

## 5. To-Be：案B 支払い方法とカードの未払いの目安

### 5.1 支出に支払い方法を付ける

| ID | 要件 |
|---|---|
| PM-01 | 普通の支出・サブスクの支払い・ほしい物の購入に、**支払い方法**（置き場所）を任意で付けられる。置き場所が2件以上あるときだけ選択欄を出す |
| PM-02 | 初期値は、設定の「いつもの支払い方法」（`User.defaultAccountId`）。普通の支出のフォームは、同じ画面で続けて記録するあいだ直前に選んだものを引き継ぐ |
| PM-03 | サブスクに「支払い方法」を登録でき（SCR-06）、支出タブの上段のサブスクの行の初期値になる |
| PM-04 | **支払い方法はゲームの判定に使わない**（G1）。精算順・手数料・報酬・貯金額は今と同じ |
| PM-05 | 支払い方法は、登録した収支のうち**金額以外で唯一あとから変えられる**項目にする（ED-01 の例外）。ゲームに影響しないので差分の解消は起きない。変更は `Resolution` に残さず、履歴に「支払い方法を変更」とだけ出す |
| PM-06 | 履歴（SCR-02）の支出の行に、支払い方法の名前を小さく出す |
| PM-07 | 引き落とし・チャージは記録の対象にしない（G2）。支出のフォームで名称に「引き落とし」「チャージ」を含むとき、二重計上の注意を出す（保存は止めない） |

### 5.2 カードの請求の区切り

| ID | 要件 |
|---|---|
| CB-01 | クレカの設定：締め日（1〜31、または末日）・引き落とし日（1〜31、または末日）・何か月後か（1 = 翌月、2 = 翌々月） |
| CB-02 | 利用日の請求月：利用日がその月の締め日以前ならその月、後なら翌月。締め日がその月にないときは末日（収入日 IN-02 と同じ寄せ方） |
| CB-03 | 引き落とし日：請求月の「何か月後」の月の引き落とし日（ない日は末日）。土日祝日による前後のずれは見ない（目安なので数日のずれは許す） |
| CB-04 | 引き落とし日の 0:00（ユーザーのタイムゾーン）を過ぎたら、その分は未払いから外れる |

> 例：15日締め・翌月10日払い。10/14 の利用 → 10月分 → 11/10 引き落とし。10/16 の利用 → 11月分 → 12/10 引き落とし。

### 5.3 未払いの目安

| ID | 要件 |
|---|---|
| CE-01 | 未払いの目安 ＝ 支払い方法がそのカードの支出（取り消したものを除く。シーズンによらず家計履歴全体）のうち、引き落とし日が今日より後のものの金額の合計 |
| CE-02 | 締め日・引き落とし日を設定していないカードは目安を出さない |
| CE-03 | 誤差調整のカードの行に「記録から見た目安 ¥xx,xxx（うち確定 ¥a・次回 m/d 引き落とし ¥b）」を出す |
| CE-04 | 入力した未払いと目安の差を行の下に出す：入力が多い →「記録より ¥c 多く使っています（記録漏れ・年会費・分割の残りかもしれません）」、少ない →「記録より ¥c 少なくなっています（返品・まだ確定していない利用かもしれません）」 |
| CE-05 | 目安を入力欄に写すボタンは置かない（カード会社の額を入れないと記録漏れが誤差に出ないため。G4） |
| CE-06 | まだ記録していないサブスクの支払い（E6b）で支払い方法がそのカードのものは、目安に足さず「未記録のサブスク ¥d」として別に並べる（差の理由がわかるように） |
| CE-07 | 電子マネー・口座・現金には目安を出さない（チャージ・入金を記録しないため。G2） |
| CE-08 | 分割・リボ・ボーナス払いは扱わない。支出は全額で記録し、目安は1回払いとして数える。実際の未払いは分割の残りを含めて入れる（AA-02）ので、差は CE-04 で説明する |

## 6. 範囲外

| 項目 | 扱い |
|---|---|
| 口座・電子マネーの残高の自動計算 | しない（入金・チャージ・給与の振込を記録しないため）。実際の額は毎回本人が確かめて入れる |
| 銀行・カード会社との連携（明細の取り込み） | しない |
| ポイント払い | ポイントで払った分を除いた額を支出として記録する（ポイントは手元のお金ではない） |
| 返品・返金 | 今の金額の編集（ED-02）で減らす。カードの返金は目安からも自動で減る |
| 年会費・手数料・利息 | 普通の支出（または年額のサブスク）として、支払い方法をそのカードにして記録する |
| 支払い方法ごとの集計・グラフ | 今回はしない |

## 7. データ・計算・画面

### 7.1 データモデル

| 変更 | 内容 |
|---|---|
| `MoneyAccount`（新規） | id・userId・name・kind（`CASH` / `BANK` / `EMONEY` / `CREDIT`）・includeInActual（初期 true）・closingDay・paymentDay（1〜31。31 は末日、クレカのみ・任意）・paymentMonths（1 / 2）・sortOrder・archivedAt・createdAt |
| `User.defaultAccountId`（追加） | いつもの支払い方法（PM-02）。`MoneyAccount` を消したら null |
| `Purchase.accountId`（追加） | 支払い方法（任意、`onDelete: SetNull`）。`@@index([accountId, date])` |
| `Subscription.accountId`（追加） | サブスクの支払い方法（PM-03） |
| `CashAdjustment.accounts`（追加） | Json?：`[{ accountId, name, kind, amount, hint }]`（amount はカードも正の数で持ち、計算で引く。hint はその時の未払いの目安）。null は合計で入力した記録 |

### 7.2 計算（[adjustments.ts](../src/server/adjustments.ts)）

- `actualOf(rows)` ＝ Σ（kind が `CREDIT` なら −amount、それ以外は +amount）。含めない置き場所の行は受け付けない（AA-04）。
- `quoteAdjustment` / `recordAdjustment` は `accounts` を受け付けたら `actual = actualOf(accounts)` とし、`actual`・`diff` の直接入力（`adjustmentInput`）と同時には受け付けない。
- `cardHints(ctx)`：カードごとに CB-02・03 で各支出の引き落とし日を出し、CE-01 の合計・次回の引き落とし日と額・未記録のサブスク（`purchaseBase` の行に `accountId` を足して絞る）を返す。保存しない（毎回その場で計算）。
- 推測の項目（`estimateItems`）は変えない（G3）。

| API | 内容 |
|---|---|
| `GET /api/accounts`・`POST /api/accounts`・`PATCH /api/accounts/:id` | 置き場所の一覧・登録・変更（使わないにする＝`archivedAt`）。`DELETE` は使っていない置き場所だけ（AC-04） |
| `GET /api/adjustments/estimate`（変更） | 置き場所の一覧、前回の内訳（AA-03）、カードの目安（`cardHints`）を加える |

| `PATCH /api/purchases/:id`（変更） | 金額に加えて `accountId` だけを受け付ける（PM-05） |
| `PATCH /api/settings`（変更） | `defaultAccountId` を受け付ける |
| サブスクの登録・変更（変更） | `accountId` を受け付ける |

### 7.4 画面

- 設定（SCR-10）：「お金の置き場所」の一覧（名前・種類・含める・カードの締め日と引き落とし日・並び替え・使わないにする）と「いつもの支払い方法」。
- 銀鉱（SCR-02）
  - 支出：普通の支出のフォームに「支払い方法」（PM-01・02）。サブスク・ほしい物の行は、行を開くと支払い方法を変えられる。
  - 誤差調整：「実際の手元の額」を置き場所ごとの行にする（AA-01〜06）。カードの行の下に目安と差（CE-03・04・06）。右上に「合計で入力 / 内訳で入力」の切り替え（AA-05）。
  - 履歴：支出の行に支払い方法（PM-06）と「支払い方法を変更」。誤差調整の行は内訳を開ける（AA-07）。
- 公園（SCR-06）：サブスクの登録に「支払い方法」。
