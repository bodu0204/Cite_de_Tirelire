## 1. 目的

支払いの手段によって、**お金が実際に減る時期**が変わる。

| 手段 | 使った時 | あとで |
|---|---|---|
| 現金・デビット | 財布・口座から減る | なし |
| クレジットカード | 減らない（未払いが増える） | 引き落とし日に口座から減る |
| 電子マネー・プリペイド | チャージ済みの残高から減る | — （チャージした時に口座から減っている） |

アプリは支出を記録した時点で手元のお金が減ったとして推測する（[record-input-redesign.md](record-input-redesign.md) §8）。カードで払ってから引き落とされるまでは、口座にお金が残っているので、実際の額が推測より多くなる（＋の誤差）。

本書では、**支出に支払い方法を記入**し、カードの締め日・引き落とし日から**まだ引き落とされていない額**を計算して、手元のお金の推測の項目（E7）に足す。これで、カードを使っても誤差調整が合うようにする。支払い方法の記入には銀貨の報酬を出し、記録の習慣の楽しみにする。

## 2. 前提と用語

### 2.1 前提

| # | 前提 |
|---|---|
| G1 | **支出は使った日に記録する（発生主義）。** カードでも現金でも同じ。精算・手数料・貯金額などゲームの判定は**支払い方法によって変えない**（節約の手応えが引き落とし日まで遅れないように） |
| G2 | **カードの引き落とし・電子マネーのチャージは支出として記録しない。** お金の置き場所が変わるだけで、増えも減りもしない（記録すると二重に引くことになる） |
| G3 | **支払い方法を記入していない支出は、現金で払ったものとして扱う。** 今までの記録・記入し忘れた記録は、何もしなくても今と同じ推測になる |
| G4 | 誤差調整の「実際の額」は、**現金 ＋ 口座 ＋ 電子マネーの残高**（カードの未払いは引かない）。カードの未払いは推測の側（E7）で足す |
| G5 | 支払い方法は、記録したあとからも記入できる。**記入すると銀貨がもらえる**（1件につき1回） |

### 2.2 用語

| 用語 | 定義 |
|---|---|
| 支払い方法 | 支出をどう払ったか。現金・クレカ・その他（デビット・電子マネー・QR決済など）（`PaymentMethod`） |
| 未記入 | 支払い方法を記入していない支出。現金として扱う（G3） |
| 締め日・引き落とし日 | カードの利用を区切る日と、その分が引き落とされる日（例：15日締め・翌月10日払い） |
| カードの未払い | 支払い方法がクレカの支出のうち、引き落とし日がまだ来ていないものの合計（§5.2）。推測の E7 |

## 3. As-Is（現状）

- 支出（`Purchase`）・サブスク（`Subscription`）に支払い方法がない。
- 誤差調整の「実際の手元の額」のヒントは「財布や口座で確かめた、自由予算の手元のお金」で、カードの未払いをどう扱うか案内がない（[AdjustTab.tsx](../src/components/records/AdjustTab.tsx)）。
- 引き落とし・チャージを支出として記録しないよう案内する表示がない。
- 収支の記録は金額だけ編集できる（ED-01）。

| # | 問題 |
|---|---|
| P1 | カードで払ってから引き落とされるまで、口座残高をそのまま入れると未払いの分の＋誤差が出る。解消すると債券が増え、引き落としのあとで−誤差になって手数料を払う（行って戻るだけで損をする） |
| P2 | 引き落とし日に請求額を支出として記録すると、二重に引かれる |
| P3 | 誤差が出たとき、カードの未払いによるものか、記録漏れかがわからない |

## 5. To-Be：カードの未払いと手元のお金の推測

### 5.1 カードの請求の区切り

| ID | 要件 |
|---|---|
| CB-01 | 利用日の請求月：利用日がその月の締め日以前ならその月、後なら翌月。締め日がその月にないときは末日（収入日 IN-02 と同じ寄せ方） |
| CB-02 | 引き落とし日：請求月の「何か月後」の月の引き落とし日（ない日は末日）。土日祝日による前後のずれは見ない |
| CB-03 | 引き落とし日の 0:00（ユーザーのタイムゾーン）を過ぎたら、その分は未払いから外れる |

> 例：15日締め・翌月10日払い。10/14 の利用 → 10月分 → 11/10 引き落とし。10/16 の利用 → 11月分 → 12/10 引き落とし。

### 5.2 推測の項目 E7

| ID | 要件 |
|---|---|
| CE-01 | 手元のお金の推測（§8.2）に **E7「カードの未払い」（＋）** を足す。支払い方法がクレカの支出（取り消したものを除く）のうち、引き落とし日が今日より後のものの金額の合計 |
| CE-02 | 数える支出は**シーズンによらず家計履歴全体**（シーズンの前にカードで払った分も、引き落とされるまで口座に残っているため） |
| CE-03 | E7 は1つのチェック（**初期チェックはあり**）。カードごとの額は E7 の下に内訳として並べる（チェックはカードごとに分けない） |
| CE-04 | カードの子の項目には「次回 m/d 引き落とし ¥b」を添える。カード会社の画面の額と比べられるように |
| CE-05 | 未記入・現金・その他の支出は E7 に数えない（G3・PM-03） |
| CE-06 | グラフ（§8.3）に E7 の行を足す。色は8色を使い切っているので、E1 の色に斜線を重ねて見分ける（E6b と同じやり方） |
| CE-07 | 誤差調整の「実際の手元の額」のヒントを「現金 ＋ 口座 ＋ 電子マネーの残高（カードの未払いは引かずに）」に変える（G4）。下に「カードの引き落とし・チャージは支出として記録しないでください」を出す |
| CE-08 | 誤差調整を保存すると、E7 の額も `CashAdjustment.items` に残る（ADJ-07） |

> 例：口座 152,000・現金 8,000（実際 160,000）。推測が E1〜E6 で 119,000、10/20 にカードで払った 41,000（11/10 引き落とし）が E7 → 推測 160,000、誤差なし。11/10 に口座が 41,000 減り、E7 も 0 になるので、引き落とし後も誤差は出ない。

## 6. 範囲外

| 項目 | 扱い |
|---|---|
| 分割・リボ・ボーナス払い | 扱わない。支出は全額で記録し、E7 は1回払いとして数える。ずれは誤差調整で解消する |
| 電子マネーの残高の計算 | しない（チャージを記録しないため）。実際の額に残高を含めて入れる |
| 銀行・カード会社との連携（明細の取り込み） | しない |
| ポイント払い | ポイントで払った分を除いた額を支出として記録する |
| 返品・返金 | 今の金額の編集（ED-02）で減らす。カードの返金は E7 からも自動で減る |
| 年会費・利息 | 普通の支出（または年額のサブスク）として、支払い方法をそのカードにして記録する |
| まだ記録していないサブスク（E6b）のカードの請求 | 今どおり E6b で数える。カードに請求済みでも、記録するまで E7 には入らない |
| 支払い方法ごとの集計・グラフ | 今回はしない |

### 7.2 計算

- `billingDate(method, date, tz)`：CB-01・02 で引き落とし日を返す（[time.ts](../src/game/time.ts) の末日への寄せ方を使う）。
- `cardUnpaid(ctx)`：`CARD` の支払い方法ごとに、その支出（金額 > 0）の引き落とし日が今日より後のものを合計し、次回の引き落とし日と額を返す。保存せず、その場で計算する。
- `estimateItems`（[adjustments.ts](../src/server/adjustments.ts)）に E7 を足す。カードごとの内訳は `GET /api/adjustments/estimate` の `cards` で返す（CE-03・04）。
- 記入の報酬は、支払い方法を記入する操作（記録・あとから記入）と同じトランザクションで出す（RW-01〜05）。

## 10. 決定事項

### 10.1 2026-11-05

| # | 論点 | 決定 |
|---|---|---|
| 方針 | 支払い方法による残高のずれ | 案B：支出に支払い方法を記入し、カードの未払いを推測（E7）で足す。支出は使った日に記録し、判定に支払い方法を使わない（G1） |
| 未記入 | 支払い方法を記入していない支出 | 現金で払ったものとして扱う（G3） |
| 報酬 | 支払い方法の記入 | 銀貨の報酬を出す。あとから記入しても出る（G5・§4.3） |

### 10.2 2026-11-14

| # | 論点 | 決定 |
|---|---|---|
| R1 | 記入の報酬の額と上限 | 1件 10S、支出の報酬とは別枠で1日 100S まで（RW-01・04）。支出の報酬の上限 300S に含めると、記録の多い日に記入の楽しみがなくなるため |

## 12. 実装で決めた細部（2026-11-14）

| 論点 | 実装 |
|---|---|
| 請求の区切りの計算 | 暦日の文字列だけで計算する（[billing.ts](../src/game/billing.ts) `billingDate`・`cardUnpaid`）。未払いを探す利用日の下限は3か月前の1日（翌々月末払いでも漏れない。`unpaidSince`） |
| 記入の報酬の数え方 | `RewardClaim.recordKey` の接頭辞 `payment:` で別枠の上限を数える（[ops.ts](../src/server/ops.ts) `grantReward` の `payment`）。記録Lv（有効な記録数）には数えない。記録の報酬の今日の合計（記録画面・状態）からも外す |
| 現金の支払い方法 | 支払い方法の一覧を最初に読むときに作る（`kind = CASH`、名前「現金」、消せない・使わないにできない） |
| 選ぶ欄を出す条件 | 有効な支払い方法が2件以上（現金のほかに登録がある）のときだけ、支出・サブスク・履歴に支払い方法を出す。登録しない人の画面は今までと同じ |
| サブスクの行の支払い方法 | 行の「支払い方法：…」を押すと選べる（初期値はサブスクに登録したもの）。API でサブスクの支払いに `paymentMethodId` を送らなければ、サブスクの登録を使う |
| チェックの保存 | `PUT /api/settings/estimate-checks` は `checksOf` で保存する（送られなかった項目は初期値。以前は保存のたびにキーの一覧を持っていたため、E7 を外しても保存されなかった） |
| 使わないにしたカード | 選べなくなるが、引き落とし前の分が残っていれば E7 と内訳に出す |
| スモークテスト | `scripts/smoke-payments.sh`（AT-083〜067） |
