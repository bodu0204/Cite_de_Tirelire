## 1. 目的

貯め方の違いが、街の違いとして見えるようにする。

| ID | 体験 | 目安 |
|---|---|---|
| H-1 | こまめに貯金すると、街が広くなる | 毎日記録して貯金を確定する人の街は、週1回の人の約2倍の広さになる（180日目） |
| H-2 | 貯金の額が増えると、技術の変化を感じる | 技術Lvが上がって3日以内に、建て替えられる建物の半分以上が新しい段階になる |
| H-3 | 無理しなくても、1日に数件の工事が完成する | 控えめ（毎月 M の10%）でも1日2件前後、標準（20%）で3件以上を、シーズンを通して保つ |

H-1 と H-2 で、街の形が貯め方を映す（同じ額を貯めたときの比べ方）。

- 毎日少しずつ → 広い街
- まとめて大きく → 狭いが新しい街
- 両方 → 広くて新しい街

（試算では、積極・毎日の 148区画に対して積極・週1回は 98区画で、建物は更新の3日後に99%が最新の段階になった。§7.2）

- **広さ（H-1）**：区画の上限は発展Lv（完成した計画の累計額＝貯めた額）で決まり、こまめさは効かない。180日目の区画は、毎日記録 27・3日に1回 20・週1回 19・記録しない 25。差は確定の遅れによる揺れで、記録しないほうが週1回より広い。
- **技術（H-2）**：技術Lvが上がっても、7日後に最新の段階にある建物は1〜16%（積極・週1回だけ39%）。建て替えは計画の順の6番目（生産効率）にあり、その前の高い計画が払えないと順番が回ってこない（GRW-03：先頭が払えなければ貯める）。新しい段階は主に新築に現れるので、技術Lvが上がっても街の見た目はほとんど変わらない。

## 3. To-Be：全体像

| 貯め方 | 何に効くか | 仕組み |
|---|---|---|
| こまめさ（貯金日の数） | 広さ（区画の上限） | こまめボーナス（§4 HAB） |
| 額（貯金額の最高到達額） | 技術（建物の段階・街の見た目） | 技術Lv は今のまま。上がったら街を一斉に建て替える（§5 TEC） |
| 毎日の建設資金 | 工事のペース | 1件の値段を、段階が上がっても上がりにくくする（§6 PAC） |
| 完成した計画の累計 | 発展Lv（村・町・都市の名前、同時工事数、建物Lvの上限、区画の上限の基本） | 今のまま（GRW-04） |

3つの仕組みは組み合わせて効く。PAC で1件を安くすると、お金ではなく土地が街の大きさを決めるようになり、その土地をこまめさ（HAB）が広げる。お金は工事のペースになり、額は技術（TEC）になる。

## 4. To-Be：こまめに貯金すると広くなる（HAB）

このゲームの貯金は、使わなかったお金が配当として毎日たまり、記録したときに確定して街に入る（REC-01）。プレイヤーがする「貯金」は記録による確定なので、こまめさは確定した日の数で測る。

| ID | 要件 |
|---|---|
| HAB-01 | **貯金日**：記録（支出・収入・貯金管理・誤差調整・今日は支出なし）で貯金を確定した暦日（ユーザーのタイムゾーン）。1日に何回記録しても1日。債券がマイナスの日（使い過ぎの日）は数えない。記録のない日の自動の確定（7日後・期間の締め）は、7日分で貯金日1日と数える。連続日数ではなく累計なので、途切れても減らない |
| HAB-02 | **こまめボーナス**：区画の上限 ＝ 発展Lvの上限（今の `PLOT_LIMIT`）＋ 貯金日の最初の7日は1日1区画 ＋ そのあとは4日ごとに1区画（`layout.ts` `habitPlots`） |
| HAB-03 | ボーナスは今の上限に足すだけなので、記録しなくても今より狭くはならない（設計原則3）。支出を正直に記録しても貯金日は減らない（設計原則5。使い過ぎの判定は債券のマイナスだけ） |
| HAB-04 | 見せ方：貯金日に上限が増えたら「こまめな貯金で、街が広がりました」と出す。区画の表示に内訳（例：発展Lv 30 ＋ こまめボーナス 12）と「あと2日の貯金で次の区画」を出す。土地が足りずに建設資金が残っているときは、ホームの次の目標に「次の区画を待っています」と出す（[savings-driven-growth.md](savings-driven-growth.md) §16.4、`home/waiting.ts` `waitingFor` に足す） |

**試した別の形**

- 区画の上限を貯金日だけで決める（発展Lvごとの最低限 4〜14 ＋ 貯金日）と、記録しない人の街は4区画・発展Lv1 のまま止まり、90日目に建設資金が83,097円残った。原則3に反するので、今の上限に足す形にした。
- 今の上限に足す形でも、自動の確定を貯金日に数えないと、記録しない人の街は4区画・発展Lv1 のまま止まった（180日目に建設資金 167,775円）。PAC で1件が安くなったため、最初の4区画に建てられる分では発展Lv2 の閾値（完成した計画 0.03M）に届かない。自動の確定を7日分で1日と数えて、記録しない人にも週1回の人と同じくらいのボーナスがつくようにした。

## 6. To-Be：1日に数件の工事（PAC）

| ID | 要件 |
|---|---|
| PAC-01 | 計画の値段 ＝ 相対コスト^α × 基準額 × κ ×（1 − 割引）（PRC-01 に指数 α を足す）。α＝0.5、κ＝0.00025。段階が上がっても1件の値段が上がりにくくなる |
| PAC-02 | 目安：1日に完成する工事（道路を除く）が、控えめ（毎月 M の10%）で2件前後、標準（20%）で3件以上、積極（40%）で5件以上。31日目以降もこれを保つ |
| PAC-03 | 区画の開拓費の伸びを 1.1^n から 1.03^n に緩める（PRC-04）。広さはこまめさで決めるので、開拓費で広さを止めない。1.1^n のままだと、こまめボーナスで区画が増える終盤に1区画が数千〜1万円を超え、工事のペースが落ちた（§7） |
| PAC-04 | 発展Lvの閾値（PRC-02）・技術Lvの閾値（PRC-03）・開拓期ボーナス・利息は変えない。発展Lvは完成した計画の累計で決まるので、入れたお金を使い切る限り、発展Lvに届く日は今とほぼ同じになる |

### 12.2 放置計算の速さ

1件が安くなると工事が増え、街も大きくなるので、組み込む前の案では1日分の計算が今の約250ミリ秒から440〜1,140ミリ秒になった（§8）。計画の消化（`develop`）が、工事を1件始めるたびと毎ティック、置ける場所・道路網・住宅と工業の隣接を作り直していたのが重かった（CPU の時間の約8割）。

- これらは盤面（建物と新築の工事の位置・系統・段階・置いたか、開いた区画、土地用途）だけで決まるので、盤面のキー（`layout.ts` `boardKey`）が変わるまで使い回す（`siteCache(s)`）。系統の建物は建ったあと動かず消えず、段階は工事の完了でだけ変わるので、キーは次のID・建物の数・区画の数・特殊施設の位置・工事のIDで足りる。
- 選んだ場所（`findSite`）・開く区画（`choosePlot`。区画の上限ごと）・住宅と工業の隣接（今の街・工事がすべて終わった街）も同じ入れ物に入れる。
- 結果は変わらない（使い回す前と後で、60日の試算の結果が同じ。決定的な放置計算の受入テストも通る）。60日の試算は 25.6秒 → 6.4秒になった。

### 12.4 組み込みで決めた細部

- **発展Lvの区画の上限を 6 / 10 / 20 / 28 / 36 / 46 に**：1件が安くなったので、その発展Lvの区画に建てられる工事の額が、次の発展Lvの閾値に届きにくくなった。発展Lv1 は初期の4区画のまま止まり（建設資金2万円・7日で、完成した計画 1,707円。発展Lv2 は 3,000円）、6区画にすると2日目に発展Lv2 になった。以前の上限（4 / 8 / 14 / 22 / 30 / 40）のままだと、週1回記録する人は発展Lv3（町）から Lv4 まで71日目までかかった（以前の規則で22日目）。6 / 10 / 20 / 28 / 36 / 46 にすると29日目になり、毎日記録する人は19日目のまま（以前と同じ）、こまめさの差（180日目に約1.9倍）も残った。
- **電力の余りを超える建て替えをしない**：無料の技術の更新で、発電所のない街の農場がすべて電力を使う機械化農場に建て替わり、食料の生産が0のまま戻らなかった。生産効率（`efficiency`）と住宅（`housing`）の建て替えは、増える電力の需要が電力の余りに収まるときだけにした（`sim.ts` `powerFits`）。電力が足りずに待つ建て替えがあるときは、収まる建て替えのあとに発電所を建てる・増築する。この分、街が大きく電力の余りが少ないと、技術の更新で建て替わるのは道路の舗装や電力を使わない建物が中心になる（§12.3）。
- **土地がなくても働き口を増やす**：住宅は建て替え・増築で上に伸びるが、仕事場は新築しか計画になく、区画の上限に当たると働き口が足りなくなった（60日目の雇用 46%）。雇用不足の解消に仕事場（工業・商業・オフィス）の建て替え・増築を足し、働き口が足りない間は景観のための住宅の増築と、技術の更新以外の住宅の建て替えをしないようにした（60日目の雇用 62%）。高い段階の住宅は仕事場より人が多く住むので、技術の更新のあとは雇用が下がる。雇用は幸福度（街の賑わい）にだけ効く（GRW-08）。
