# シーズン開始時の設定 As-Is / To-Be

作成日：2026-11-16
関係：[requirements.md](requirements.md) §2.1・§3.2・§4.9・§5・SCR-01・SCR-10、[savings-driven-growth.md](savings-driven-growth.md) RSV-01〜03・PRC-05、[bond-and-custom-currency.md](bond-and-custom-currency.md) BND-12・§4.3、[money-accounts.md](money-accounts.md) §4・§7、[record-input-redesign.md](record-input-redesign.md) §5、[Onboarding.tsx](../src/components/home/Onboarding.tsx)、[ops.ts](../src/server/ops.ts) `startSeason`

## 1. 目的

シーズンを始める時点の現実（すでにある貯金、月の途中の残りの予算、口座の残高、カードの未払い）を、ゲームが知らないまま始まっている。開始時にこれらを聞いて、最初の日からゲームと現実が合うようにする。

採用した項目は次の6つ。

| # | 項目 | 節 |
|---|---|---|
| 1 | すでにある貯金を**備えとして持ち込む** | §4 |
| 2 | 前のシーズンの備えを**次のシーズンに持ち越すか選べる** | §5 |
| 3 | **目標の名前** | §6 |
| 4 | **今期の残りの自由予算** | §7 |
| 5 | **収入日を初回に聞く** | §8 |
| 6 | **置き場所の開始残高とクレカの未払い** | §9 |

## 2. As-Is（今の作り）

- シーズン開始で入れるのは **月間自由予算** と **貯金目標額** の2つだけ（`POST /api/season`）。
- すでにある貯金は、入力欄のヒント（「今の預金残高ではなく、これから新しく貯める金額」）で目標額から外してもらうだけで、ゲームには無い。債券は 0 から始まる。
- 新シーズンで債券は 0 に戻る（マイナスも持ち越さない。BND-12）。
- 金貨の配当は、開始した時刻から収入期間の終わりまでを時間で按分する。
- 収入日は設定画面だけで変えられ、初期値は毎月1日。
- お金の置き場所は設定画面で登録する。開始残高を入れなければ 0。

| # | 問題 |
|---|---|
| P1 | 貯金があっても、開始直後に大きな買い物をすると債券がマイナスになり、配当の20%以上が強制的に債券へ回る。現実には貯金から出しただけである |
| P2 | 貯金があっても備えLvは 0 で、最初の悪い出来事をそのまま受ける |
| P3 | 目標を達成して次のシーズンを始めると、貯めた備えが街から消える（現実の貯金は残っている） |
| P4 | 街・タイムラプスが「シーズン1」としか呼ばれず、何のための貯金だったかが残らない |
| P5 | 月の途中で始めると、実際の残りの予算と按分した配当が合わない（月初に多く使った人は最初から足りない） |
| P6 | 収入日を設定で変えるまで、配当の区切りが実際の給料日と合わない。初回は気づきにくい |
| P7 | 置き場所の残高を入れずに始めると、最初の照合で大きな誤差が出る。開始前に使ったカードの引き落としがシーズン中に来る |

## 3. 開始画面の形

| ID | 要件 |
|---|---|
| ST-01 | 必須は今と同じ **月間自由予算** と **貯金目標額** の2つだけ。ほかの項目は入れなくても始められる（入れなければ今と同じ動き） |
| ST-02 | 画面は1枚で、上から **目標**（名前・目標額）、**毎月のお金**（月間自由予算・収入日・今期の残り）、**すでにある貯金**（持ち込みの備え）、**お金の置き場所**（任意）の順に並べる |
| ST-03 | 2回目以降は、前のシーズンの値を初期値にする（月間自由予算・収入日。目標の名前と目標額は空） |
| ST-04 | 「街をつくる」を押す前に、入れた内容で最初の日がどうなるかを1行ずつ添える（例：「今期の残り 12日で 18,000G が配当されます」「備えLv2 から始まります」） |

## 4. 備えとして持ち込む

すでにある貯金のうち「もしものときに使ってよい分」を申告すると、**持ち込みの備え**として街の備えに数える。街を育てる力（建設資金・技術Lv・達成率）には数えない。

### 4.1 考え方

債券そのものを初期値として配ると、貯金額（＝債券＋使った金貨）が最初から増え、達成率・技術Lv・利息・同額の建設資金がついてしまう。そこで債券は 0 から始め、**債券の下に敷くクッション**として別に持つ。

```
  債券 ＋ 持ち込みの備え  → 備えLv の判定
  債券（0〜上限）          → 利息・同額の建設資金（今と同じ）
  債券 ＋ 使った金貨       → 貯金額・達成率・技術Lv（今と同じ）
  債券 < −持ち込みの備え   → 借金の扱い（配当の強制の債券化）
```

### 4.2 要件

| ID | 要件 |
|---|---|
| RC-01 | シーズン開始時に **持ち込みの備え**（円、0 以上）を入れられる。入れなければ 0（今と同じ） |
| RC-02 | 上限は債券の上限と同じ 3M（月間自由予算の3か月分）。超える額を入れたら 3M に丸め、「備えに数えるのは 3か月分までです」と添える |
| RC-03 | 貯金用の置き場所があれば、その残高の合計（3M まで）を入力欄の初期値にする。前のシーズンがあれば §5 の値を優先する |
| RC-04 | **備えLv** は 債券 ＋ 持ち込みの備え で判定する（0.5 / 1 / 2 / 3 か月分）。備えの施設（防災倉庫など）も同じ |
| RC-05 | **利息**・**同額の建設資金**・**貯金額**・**達成率**・**技術Lv**・**開拓期ボーナス**には数えない。債券だけで今のとおり計算する |
| RC-06 | 購入の精算で債券から払う分は今と同じ（債券が減り、マイナスになる。手数料も同じ）。使い過ぎは貯金額を減らす。**持ち込みの備えは減らさない**（債券のマイナスが取り崩しを表す） |
| RC-07 | 債券が **−持ち込みの備え 以上**の間は借金として扱わない：配当の強制の債券化（20%）をしない。債券化率は自分で決めた値のまま |
| RC-08 | 債券が −持ち込みの備え を下回ったら、今のマイナスの債券と同じ扱い（強制の債券化）。−持ち込みの備え まで戻れば解ける |
| RC-09 | 債券がマイナスで −持ち込みの備え 以上の間は、債券の表示に「持ち込みの備えから ◯円 取り崩し中」と添える。赤字（危険の色）にはしない |
| RC-10 | 債券がマイナスの間、利息がつかない・マイナスを 0 に戻す分に建設資金がつかない・貯金日（こまめボーナス）に数えないのは今と同じ（取り崩しは使い過ぎである） |
| RC-11 | 持ち込みの備えはシーズン中に変えられない（基準額と同じ。PRC-05）。開始から24時間以内だけ直せる（誤入力のため） |
| RC-12 | 銀行の画面の備えの欄に、債券と持ち込みの備えを分けて出す（「備え ¥150,000 ＝ 債券 ¥30,000 ＋ 持ち込み ¥120,000」） |

> 例：M＝6万円、持ち込みの備え 12万円。開始時は債券 0・備えLv3（2か月分）。3日目に 2万円の買い物で金貨が 5,000G しかなければ、債券 −15,000（手数料 50S）、備えLv2（10.5万円）。強制の債券化はなし。貯金額は −15,000 から数え直しになる。

## 5. 次のシーズンに持ち越す

| ID | 要件 |
|---|---|
| CO-01 | 前のシーズンが完了しているとき、開始画面の「すでにある貯金」に **前の街の備え ¥X** を出し、持ち込むかどうかをチェックで選べる（初期値はあり） |
| CO-02 | X ＝ 前のシーズンの完了時の 債券 ＋ 持ち込みの備え（0 未満は 0。新しい月間自由予算の 3M まで） |
| CO-03 | チェックありなら X を持ち込みの備えの入力欄に入れる。金額は直せる（現実に使った・足した分に合わせる） |
| CO-04 | チェックを外すと 0 から始まる（今と同じ） |
| CO-05 | 持ち越すのは備えだけ。貯金額・達成率・技術Lv・建設資金・金貨・銀貨・ユーザ通貨の残高は今のとおりリセットする |
| CO-06 | 前のシーズンの債券のマイナスは持ち越さない（今と同じ。BND-12） |
| CO-07 | 持ち越したことをシーズンの最初のイベントに残し、タイムラプスの最初に「前の街から備え ¥X を持ち込んだ」と出す |

## 6. 目標の名前

| ID | 要件 |
|---|---|
| GN-01 | シーズン開始時に **目標の名前** を入れられる（任意、20文字まで。例：「北海道旅行」「引っ越し」） |

## 7. 今期の残りの自由予算

| ID | 要件 |
|---|---|
| RB-01 | シーズン開始時に **今期の残りの自由予算**（次の収入日までに自由に使える額）を入れられる。入れなければ今と同じ按分 |
| RB-02 | 入力欄の初期値は按分の額：(B − S − C) × 期間の残り時間 ÷ 期間の長さ。「次の収入日（◯月◯日）まで あと◯日」と添える |
| RB-03 | 入れた額 R と按分の額 P の差を、**最初の収入期間の配当だけ**に入れる。R > P なら差を今から期間の終わりまで均等に上乗せする。R < P なら差を残りの配当から減らす |
| RB-04 | R は 0 以上、月間自由予算 B 以下 |
| RB-05 | ユーザ通貨の発生（C）は変えない。R は金貨として配る分だけを指す |
| RB-06 | 次の収入期間からは今のとおり（月の収入の雛形で配当） |
| RB-07 | この調整は収入の記録ではない。銀貨の報酬・差分の解消・記録Lvには数えない |
| RB-08 | 開始後は直せない（その期間の月の収入の記録で差分を入れられる） |

> 例：B＝6万円、30日の期間の20日目に開始。按分は 2万円。実際の残りが 8,000円なら、残り10日で 8,000G が配当される。

## 8. 収入日を初回に聞く

| ID | 要件 |
|---|---|
| PD-01 | 開始画面に **毎月の収入が入る日**（1〜31）を出す。初期値は今の設定（初回は1日） |
| PD-02 | シーズンが1つもない人（初回）は、選んだ日を**すぐに**反映する（最初の期間からその日で区切る） |
| PD-03 | 2回目以降は設定画面と同じ（次の収入日から反映）。その旨を添える |
| PD-04 | 収入日を変えると、RB-02 の「あと◯日」と按分の額をその場で出し直す |

## 9. 置き場所の開始残高とクレカの未払い

| ID | 要件 |
|---|---|
| OA-01 | 開始画面の最後に「お金の置き場所」を出す。設定画面と同じ登録（名前・種類・開始残高・クレカの締め日など）がその場でできる |
| OA-02 | 飛ばせる（「あとで設定する」）。入れなければ今と同じ（財布Aだけ、残高 0） |
| OA-03 | 初回は、財布A の開始残高の欄と、「口座を足す」「クレカを足す」のボタンを出す |
| OA-04 | クレカは「今の未払い（カード会社の画面のご利用額）」を正の数で入れる（今と同じ。AC-05） |
| OA-05 | 2回目以降は、置き場所ごとの計算した残高を並べ、「残高を合わせる」（照合）へ誘う。開始残高は書き換えない |
| OA-06 | 開始残高の未払いがあるクレカの最初の引き落とし予定に、「開始前の利用 ¥X が含まれているか確かめてください」と添える（予定の額は今のとおり記録から計算し、確定のときに直す） |
| OA-07 | 貯金用の印をつけた置き場所の残高は、RC-03 の初期値に使う |

## 10. 範囲外

| 項目 | 扱い |
|---|---|
| すでにある貯金を目標のゲージに出す（「50万 → 100万」） | 今回はしない。目標額は今のとおり新しく貯める額 |
| すでにある貯金で街の出発点を上げる（建設資金・発展Lv） | しない（貯めた分だけ街が育つ） |
| 先取り貯金（毎月の積立）を目標に数える | 今回はしない |
| 目標の期限・節目のごほうび | 今回はしない |
| 開始日の予約（次の収入日から） | 今回はしない |
| 金貨・銀貨・記録Lvなどの持ち越し | しない（CO-05） |

## 14. 確認したいこと

| # | 論点 | 今の案 |
|---|---|---|
| Q1 | 持ち込みの備えの上限 | 3M（備えLv4 まで届く）。最初からすべての悪い出来事を防げてしまうので、2M（備えLv3 まで）に抑える案もある |
| Q2 | 持ち込みの備えの範囲内の取り崩しの手数料 | 今の債券と同じ（10%、上限 50S）。なしにすると申告した人が得をする |
| Q3 | 持ち越しを選ぶ場所 | 次のシーズンの開始画面（CO-01）。完了の画面で選ぶ案は、次を始めるまでに現実が変わるので採らない |
| Q4 | 目標の名前を街の名前としても使うか | 使う（別に街の名前は持たない） |
| Q5 | 今期の残りが按分より少ないとき、ユーザ通貨の発生も減らすか | 減らさない（RB-05） |
| Q6 | 開始残高の未払いを最初の引き落とし予定の額に自動で足すか | 足さない（翌々月払いだと、どの予定に入るかがわからない。OA-06 の注意だけ） |
