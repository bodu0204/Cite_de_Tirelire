## 1. 目的

銀鉱（記録）の入力を、**収入・支出・誤差調整**の3種類に整理する。貯金（追加・引出）の記録は**貯金管理**として銀鉱の別の項目にまとめる。

- **収入**：月の収入（月間自由予算と通貨配分設定が雛形）と臨時の収入を記録する。**通貨の配当は月の収入の記録から生まれ、収入日を基準に始まる**。雛形との差分や臨時の収入を、どの通貨に・いつ・どう振り分けるかを決められ、入力時に資源のおまかせ購入もできる。
- **支出**：普通の支出に加えて、サブスク・ほしい物の支払いを設定から作ったベースで「保存」ボタンひとつで記録できる。ベースとの差分は決まったルールで解消する。
- **誤差調整**：ゲームの状態から推測した「手元にあるお金」を、項目のチェックで組み立てて表示し（グラフつき）、実際との誤差を入力して解消できる。

差分の解消は共通のルールにする（§4）。登録した収支は金額だけ編集でき、金額の変化も同じルールで解消する（§9.3）。

## 2. 前提と用語

### 2.1 前提（2026-10-20 指示）

| # | 前提 |
|---|---|
| F1 | 今の月間自由予算 B と通貨配分設定（サブスク・ユーザ通貨の発生ルール・債券化率）を、**月の収入の雛形**にする |
| F2 | **月の収入の記録に対して、実質の各種配当（金貨の採掘・ユーザ通貨の発生・債券化）が生まれる** |
| F3 | **貯金額 ＝ 債券を含む、都市に使った現実のお金。** 金貨はゲーム内で使っても現実のお金は出ていかないので、都市に使った金貨はそのまま貯金になる。債券は現実の支払いに使うと、その分貯金が減る |
| F4 | 貯金（追加・引出）の記録は**貯金管理**にまとめ、手元のお金の推測に使う（貯金を別口座に移した場合を考えるため） |

### 2.2 用語

| 用語 | 定義 |
|---|---|
| B | 月間自由予算（`User.monthlyBudget`）。月の収入の雛形の金額 |
| 収入日 | 毎月の収入が入ってくる日（`User.incomeDay`、1〜31。設定がなければ1日）。配当はこの日を基準に始まる（§5.1） |
| 収入期間 | ある月の収入日から翌月の収入日の前日まで。月の収入1件に対応する。配当・採掘・精算の「月」はこの期間（§5.1） |
| 雛形 | B と通貨配分設定から作る、月の収入の初期値と配当の割り振り（§5.2） |
| 配当 | 月の収入・臨時の収入から通貨（金貨・ユーザ通貨・債券）が生まれること。金貨の配当は採掘（時間で少しずつ）、ユーザ通貨はルールの発生日 |
| 未配当分 | 記録した（または雛形で見込んだ）収入のうち、まだ通貨になっていない額（§8.2） |
| 差分 | 実際の額 − ベース を、**手元のお金から見た向き**で表したもの。手元のお金が予定より多くなる向きを **＋差分**、少なくなる向きを **−差分**（§4.1） |
| 即時貯蓄 | ＋差分の解消と同じ「債券 → おまかせ交換」に、その場で入れること（§4.2） |
| 振り分け | 収入（差分・臨時）を、量・通貨・時期・方法の組で通貨に入れる指定（§5.5） |
| おまかせ交換 | 金貨を都市の必要資源の割合で資源・都市資金に交換すること（needs-based-exchange.md §5） |
| 貯金額 | 債券 ＋ 都市に使った金貨の累計（§7.1） |
| 貯金管理 | 貯金（追加・引出）の記録。別口座への出し入れを表す（§7.2） |
| 手元のお金の推測 | §8 の項目のうち、チェックしたものを足し引きした額 |
| 債券上限 | 3M（M ＝ B。`bondCap`） |

- 1G ＝ 1円相当（D-9）、ユーザ通貨も 1単位 ＝ 1円相当。

## 3. As-Is（現状）

### 3.1 記録画面（SCR-02、[records/page.tsx](../src/app/(game)/records/page.tsx)）

- タブは「購入を記録」「貯金を記録」「記録履歴」の3つ。
- **収入を記録する手段がない。** B は設定値で、金鉱が毎分 (B − S − C) ÷ 月の分数 を自動で採掘し（[mine.ts](../src/game/mine.ts) `accrue`）、ユーザ通貨は発生ルールの日に自動で発生する。**配当は設定から生まれていて、記録とは関係がない。** 実際の月収が B と違っても反映できない。
- 採掘の「月」は暦の月（1日 0:00〜月末、ユーザーのタイムゾーン。[time.ts](../src/game/time.ts) `monthRange`）で固定。給料日が月の途中でも区切りは1日。
- 臨時の収入（ボーナス・お祝い・払い戻しなど）を通貨にする手段もない。

### 3.2 購入（[ops.ts](../src/server/ops.ts) `recordPurchase`・`editPurchase`・`settle`、[settle.ts](../src/game/settle.ts) `pay`）

- 金額・日付・名称（必須）、ジャンル・メモ（任意）、「サブスクの支払い」フラグ、ほしい物の紐付け。
- 精算順：像の積立金貨（紐付けたほしい物のみ）→ ジャンルが一致するユーザ通貨 → 未回収金貨 → 所持金貨 → 債券（マイナス可）＋銀貨の手数料。
- 当月以外の日付、サブスクの支払い、シーズン外の記録は精算しない。
- 記録前に支払い内訳をプレビューできる（`/api/purchases/quote`）。
- **編集では金額・日付・名称・ジャンル・メモ・サブスクフラグのすべてを変えられる。** 増額は同じ精算順で追加精算し、減額は逆順（債券 → 所持金貨 → ユーザ通貨）で払い戻す。ジャンルが変わると全額を戻して精算し直す。締めた月の記録は精算し直さない。削除もできる。

### 3.3 サブスクの支払い（SCR-06）

- サブスクの登録内容から月額換算 S を採掘から差し引いている。
- 支払いの記録は、購入フォームで毎回 金額・名称を手入力し「サブスクの支払い」にチェックを入れる。登録済みのサブスクとは**紐付かない**。
- 「サブスクの支払い」は精算しないので、**登録額と実際の請求額がずれてもゲームには反映されない。**

### 3.4 ほしい物の購入（SCR-05）

- 購入フォームでほしい物を選ぶと、積立金貨を min(積立, 購入額) だけ精算に充て、残りは通常の精算順で払う。
- 金額はほしい物の価格から入らず、毎回手入力する。
- 購入額が積立より安かったとき、**余った積立金貨は像に残ったままになり、使い道がない。**

### 3.5 貯金と見込み貯金（requirements.md 3.6、[levels.ts](../src/game/levels.ts)）

- 貯金（追加・引出）の記録の純増額が、技術Lv・銀行Lv・目標達成の判定の根拠。回数の制限はない（報酬は1日の上限 300S まで）。
- 金貨で資源・都市資金を得た額は「見込み貯金」（`Season.estimatedSavings`）に加わり、**貯金を記録すると0に戻る**（実額に置き換わる）。
- 表示の達成率 ＝ (純増額 ＋ 見込み ＋ 債券) ÷ 目標（`projectedRate`）。
- 「手元にいくらあるはずか」を表示する機能はない。

### 3.6 現状の問題

| # | 問題 |
|---|---|
| P1 | 収入の記録がなく、配当が設定からだけ生まれる。実際の月収と B の差がゲームに入らない |
| P2 | 臨時の収入を通貨にできない |
| P3 | サブスク・ほしい物の支払いを毎回手入力する必要がある |
| P4 | サブスクの請求額のずれ、ほしい物の値引きが反映されない（余った積立金貨が残る） |
| P5 | 都市に使ったお金（見込み貯金）が、貯金の記録で消えてしまう。別口座に移したことと、都市に使ったことが区別されない |
| P6 | 記録漏れに気づく手段がなく、気づいても直し方がばらばら |
| P7 | 採掘の区切りが暦の月で、収入が入る日とずれる |

## 4. To-Be：差分の解消ルール（共通）

### 4.1 差分の向き

| 記録 | ＋差分（手元が予定より多い） | −差分（手元が予定より少ない） |
|---|---|---|
| 月の収入 | 実際の月収 ＞ 雛形 | 実際の月収 ＜ 雛形 |
| 臨時の収入の編集 | 増額 | 減額 |
| 支出の編集 | 減額 | 増額 |
| サブスクの支払い | 請求額 ＜ 登録額 | 請求額 ＞ 登録額 |
| ほしい物の購入 | 購入額 ＜ 価格（積立が余る） | 購入額 ＞ 価格 |
| 誤差調整 | 実際の手元 ＞ 推測 | 実際の手元 ＜ 推測 |

※ 月の収入の＋差分と臨時の収入は、§4.2 ではなく §5.5 の振り分けで配当する（初期値は §5.5 の表）。月の収入の−差分は、未配当分から先に減らす（IN-17）。

### 4.2 ＋差分：債券 → おまかせ交換

| ID | 要件 |
|---|---|
| RC-01 | ＋差分 d は、まず債券に入れる。入れる額は min(d, max(0, 上限 − 債券))。債券がマイナスならその返済にも充たる |
| RC-02 | 債券に入った分のうち 0〜上限の範囲に入る分には、これまでどおり同じ量の金貨でおまかせ交換した資源がつく（needs-based-exchange.md §6.2 の式。手数料なし） |
| RC-03 | 債券が上限に達して入りきらない残りは、金貨としておまかせ交換する。**手数料は1回 5S。銀貨が足りないときは手数料なしで交換する**（Q7）。この額は都市に使った金貨（貯金額の債券以外。§7.1）に加える |
| RC-04 | 確定前に「債券 +x（資源つき y）・おまかせ z G → 木材・石材・食料・都市資金」をプレビューする |

> 例（M ＝ 60,000、上限 180,000）：債券 175,000 のとき ＋差分 8,000 → 債券に 5,000（資源つき 5,000）、残り 3,000G をおまかせ交換。

### 4.3 −差分：債券

| ID | 要件 |
|---|---|
| RC-11 | −差分 d は、**全額を債券から減らす**（マイナス可）。金貨・ユーザ通貨・未回収金貨は使わない（2026-10-21 変更） |
| RC-12 | 債券から減らした分には、購入と同じ銀貨の手数料（使った債券の10%、上限50S、銀貨の不足分は債券から）をかける。誤差調整にもかける（Q8。＋−の繰り返しで資源を増やす抜け道を抑える） |
| RC-13 | 債券から減らした分は、その収入期間の `MonthlyOverspend` に加える。貯金額もその分減る（F3） |
| RC-14 | 債券がマイナスになったら、今と同じく採掘の max(r, 20%) を債券に回して0に戻す（BND-07） |
| RC-15 | 過去に得た資源・建物は没収しない（設計原則4） |

> 例：債券 10,000・銀貨 30S のとき −差分 2,000 → 債券 −2,000、手数料 50S のうち銀貨 30S・不足 20 を債券から → 債券 7,980、銀貨 0S。

> 補足：−差分で金貨を減らさないので、手元に金貨が多くても債券が先に減る。手元の金貨は精算（普通の支出）・交換で使う。債券は「急な出費の備え」なので、予定外に手元が減った分（−差分）を受け持つ、という整理にする。

### 4.4 計算の置き場所

- [settle.ts](../src/game/settle.ts) に `absorbSurplus(purse, d, needs, lv)`（RC-01〜03）と `absorbShortfall(purse, d, payments)`（RC-11〜13。債券と手数料だけを動かす。手数料は `settleFee` を使う）を追加し、記録の種類によらず共通に使う。
- 解消の内訳は支払い内訳と同じ形（`Payment[]`）で記録ごとに保存し、金額の編集のたびに追記する（§9.3）。

## 5. To-Be：収入

### 5.1 収入日と収入期間

| ID | 要件 |
|---|---|
| IN-01 | 設定（SCR-10）で毎月の**収入日**（1〜31日）を決められる。設定がなければ1日 |
| IN-02 | ある月の収入期間は「その月の収入日 0:00 〜 翌月の収入日 0:00」（ユーザーのタイムゾーン）。収入日がその月にない日（例：31日で11月）は、その月の末日にする |
| IN-03 | 月の収入の配当は**収入日を基準に発生する**：金貨の採掘は収入期間の分数で割った速度で進み、雛形の C（ユーザ通貨の発生額）・S（サブスク）も収入期間ごとに数える |
| IN-04 | 収入期間は「その収入日がある月」の名前で呼ぶ（例：収入日 25日なら「10月の月収」＝ 10/25〜11/24）。monthKey もその月 |
| IN-05 | 次のものも暦の月から収入期間に揃える：支出の精算の「当月」（当月以外は精算しない）、`MonthlyOverspend` の区切り、金鉱画面の当月採掘・当月精算、ユーザ通貨の「月の発生額 C」と B − S − C の確かめ（予算超過の拒否）※Q15 |
| IN-06 | 収入日を変えたら、**次の収入日から**新しい区切りにする。変更した時点の収入期間は、新しい収入日の前日までを1期間として延ばす・縮める（その期間の採掘速度は、残りの額 ÷ 残りの分数で計算し直す） |
| IN-07 | ユーザ通貨の発生ルール（毎週・毎月◯日など）の日付そのものは変えない。C の数え方の区切りだけを収入期間にする |

> 例（収入日 25日、B ＝ 60,000、S ＝ 6,000、C ＝ 28,000）：10/25 0:00〜11/25 0:00（31日 ＝ 44,640分）に 26,000G を採掘する（毎分 約 0.582G）。

### 5.2 雛形と配当

| ID | 要件 |
|---|---|
| IN-11 | 月の収入の雛形は、B と通貨配分設定から作る（F1）。雛形の金額は B、割り振りは今の採掘と同じ：サブスク S（差し引き）、各ユーザ通貨の発生額 C（発生ルールの日）、残り B − S − C を金貨として収入期間の分数で採掘（うち債券化率 r の分は債券） |
| IN-12 | **配当は月の収入から生まれる**（F2）。記録した期間は、記録した金額のうち雛形の分を雛形の割り振りで、差分を §5.5 の振り分けで配当する |
| IN-13 | 記録していない期間（当期で未記録・過去の記録忘れ）は、**雛形で配当を続ける**（Q11。記録を忘れても不当に損をしない。設計原則3）。あとで記録すると差分だけを配当する |
| IN-14 | 雛形の分の配当は今の仕組み（金鉱の `MinePlan`・ユーザ通貨のロット）のまま。記録は「その期間の収入額」を確定させ、差分の配当を追加する |

### 5.3 月の収入の記録

| ID | 要件 |
|---|---|
| IN-15 | 未記録の期間について、**自由予算・現在の日付・記録済みのデータからベースを作り**、期間ごとに1行ずつ並べる。例：`7月の月収 60,000円 [保存]`・`8月の月収 60,000円 [保存]`・`9月の月収 60,000円 [保存]`・`[一括保存]` |
| IN-16 | 並べる期間：シーズン開始時点の期間（または最後に記録した期間の次）から、収入日が来ている最新の期間まで。**ベースは今の B**（予算の変更履歴は持たない。過去の期間はベースを手で直す）（Q2） |
| IN-17 | −差分（月収が雛形より少ない）は、**その期間のまだ配当していない分（残りの採掘・未発生のロット）から減らし、足りなければ債券**（§4.3、手数料あり）で解消する（Q3）。未配当分から減らすときは、残りの採掘速度を下げる（金貨の分から先に、ユーザ通貨の未発生分はそのあと）。過去の期間は未配当分がないので全額が債券 |
| IN-18 | 行ごとの [保存] でその期間を記録する。[一括保存] は表示中の全行を、それぞれの入力値で保存する。1期間に記録できる月の収入は1件だけ（`userId × monthKey` で一意） |
| IN-19 | 行の金額を変えると、**自由予算に対する一時的な変動**（その期間だけの差分）になる。B（設定）は変わらない |
| IN-20 | 差分 0 で保存した期間は「雛形どおり」という確認の記録になり、追加の配当はない |
| IN-21 | ＋差分は §5.5 の振り分けで配当する。初期値は通貨配分設定の割合（§5.5 の表）。変更できる |
| IN-22 | 入力時に「おまかせで資源を買う」を選ぶと、即時に配当する金貨をそのままおまかせ交換する（手数料1回 5S、銀貨が足りなければなし。都市に使った金貨に加える） |
| IN-23 | 報酬は購入と同じ 50S。月の収入は `income:<monthKey>` で期間ごとに1回（一括保存で複数期間を入れても期間ごと。1日の上限 300S は共通）（Q10） |

### 5.4 臨時の収入

| ID | 要件 |
|---|---|

### 5.5 振り分け

振り分けは次の行の組。合計は振り分ける額（月の収入の＋差分、または臨時の収入の全額）と一致させる。

| 項目 | 選べる値 |
|---|---|
| 量 | 円（または割合％。端数は最後の行に寄せる） |
| 通貨 | 即時貯蓄（債券 → おまかせ交換） / 金貨 / 債券 / ユーザ通貨（いずれか1つ） |
| いつ | 即時 / 指定日（1日〜複数日） / 期間で均等（開始日〜終了日）。即時貯蓄は即時だけ |
| どう | 一括 / 日ごと均等 / 毎分（期間で均等のとき） |

- 即時貯蓄：§4.2 の ＋差分と同じ（債券に上限まで入れて資源つき、入りきらない分はおまかせ交換・手数料 5S）。
- 金貨：即時・指定日は所持金貨に入れる。期間で均等（毎分）は、その期間だけ採掘に上乗せする（金鉱の `MinePlan` に一時的な区間を足す。債券化率もかかる）。
- 債券：上限までは資源がつき、上限を超える分は金貨に入れる（ユーザ通貨の余りと同じ。おまかせ交換はしない）。
- ユーザ通貨：指定日に、その日に発生したロットとして入れる。期限・余りの扱いは通貨の定義に従う。
- **プリセット**：振り分けの入力欄の上で切り替える。切り替えると入力中の行はそのプリセットの行に置き換わり（雛形）、そこから自由に直せる。直したあとにプリセットを切り替えるときは、置き換えてよいか確かめる。

  | プリセット | 行 | 量 | 通貨 | いつ・どう | 初期値になる記録 |
  |---|---|---|---|---|---|
  | 即時貯蓄 | 1行 | 全額 | 即時貯蓄 | 即時 | 臨時の収入 |
  | 通貨配分設定の割合 | 各ユーザ通貨 | 額 × その期間の各通貨の発生額 ÷ B | そのユーザ通貨 | その期間の残りの発生日に分けて（残りがなければ即時） | 月の収入の＋差分 |
  | 〃 | 残り | 額 − 上の合計 | 金貨（うち債券化率 r の分は債券） | その期間の終わりまで毎分（過去の期間なら即時） | 〃 |
  | 全額を金貨に即時 | 1行 | 全額 | 金貨 | 即時 | — |

- 予約した分（指定日・期間）は、放置計算のティックで期日が来たときに入れる（§9.2）。予約中の分は記録の詳細に「予定」として表示する。

### 8.3 グラフ

- **積み上げの横棒（ウォーターフォール）**：チェックした項目を左から順に積み上げ、E5 のマイナスは棒を左へ戻す形で描く。右端が推測の額。
- チェックしていない項目は、棒の外側に薄い色の点線で「足したらここまで」を示す（チェックすると実線になる）。
- 実際の手元の額を入力すると、縦の目印を引き、推測との差（誤差）を ＋ は緑・− は赤の区間で示す。
- 項目の色は凡例と表で揃え、色だけに頼らず項目名と額を棒の下に並べる（WCAG 2.2 AA）。
- 描画はインラインの SVG（追加のライブラリなし）。チェックを変えると即時に再描画する（サーバーへの問い合わせなし。項目の額は1回の取得で全部返す）。

### 8.4 「その月の配当分」の数え方

- 金貨に**生まれた収入期間**を持たせる（期間ごとの残高 `Season.goldByPeriod`）。採掘・回収・配当は当期の分に、臨時の収入（即時の金貨）は「配当分以外」に入れる。
- 金貨を使う（精算・交換・積立）ときは、**古い期間の分から**使う（先入れ先出し）。期間が替わると前の期間の分は「配当分以外」になる。
- ユーザ通貨はロットの発生日、像の積立金貨は積み立てた期間で判断する。
- 未回収金貨はすべて当期の配当分（期間が替わるときに前の期間の分は回収済みとして扱う、今の採掘の区切りに合わせる）。

### 9.5 画面

- 銀鉱（SCR-02）のタブを **収入 / 支出 / 誤差調整 / 貯金管理 / 履歴** にする。
  - 収入：上段に未記録の期間の行（`7月の月収 [60,000] 円 [保存]`…`[一括保存]`。期間の日付も小さく出す）。行を開くと差分の振り分け（§5.5）と「おまかせで資源を買う」。下段に臨時の収入のフォーム（振り分けの初期値は即時貯蓄）。
  - 支出：上段にサブスクとほしい物の行（ベース・差分・[保存]・[一括保存]）、下段に普通の支出のフォーム。
  - 誤差調整：§8.2 の項目のチェックリスト（額つき）、グラフ（§8.3）、推測の額、実際の額の入力、誤差と解消のプレビュー。
  - 貯金管理：貯金（追加・引出）の記録と履歴、今日の残り回数（「今日はあと2回」）、貯金額（債券・債券以外）と貯金管理の増減。
  - 履歴：収入・支出・誤差調整を日付順に並べ、解消の内訳（債券・おまかせ・金貨）と金額の変更履歴を表示する。収支の行には「金額を変更」だけを置く（削除ボタンはなくす）。
- 設定（SCR-10）：収入日を追加（「毎月の収入が入る日」。31日などは月末に寄せる旨を添える）。変更すると次の収入日から反映される旨を表示する。
- 銀行（SCR-04）：貯金額（債券・債券以外）・最高到達額・技術Lvの根拠を表示する。
