## 1. プロダクト概要

**日々の節約・支出管理・貯金を、街づくりの楽しさに変換する放置型育成ゲーム。**

- プレイヤーは現実の自由予算・購入・貯金を記録する。
- 街は **貯金（使わなかったお金）を建設資金にして** 計画を1件ずつ建てて発展する。貯めた分は放っておいても数時間〜数日かけて形になる（操作を続ける義務はない）。
- **貯金額（債券 ＋ ゲーム内で使った金貨＝現実で使わなかったお金）が技術Lvを上げ**、新しい建物や技術が解放される。
- ゲームの目的は街の最大化ではなく、**現実の貯金目標を達成すること**。目標達成が街のエンディングになり、成長の歴史がタイムラプスとして残る。

> 日々の生活で貯めたお金が、街の建設資金になる。記録すると貯金が確定し、債券（もしもの備え）が街を守る。

### 1.1 設計原則

1. 現実の金銭管理とゲーム内経済を明確に区別する（ゲーム内通貨は換金不可、積立は現実の預金の証明ではない）。
2. お金を多く使うことより、節約と継続を有利にする（記録報酬は金額に比例しない）。
3. 記録を忘れたりログインしなかったりしても不当に損をしない（放置で成長する）。
4. 予算超過・貯金の減少・資源不足で、建設済みの街を破壊しない。
5. 現実の支出を隠すことが有利にならない。
6. 1つの目標達成ごとに1つの街の物語が完結する。

### 1.2 プレイサイクルとフェーズ

| フェーズ | 内容 | プレイヤーの主な行動 |
|---|---|---|
| Phase 1 初期開拓（初回10〜20分） | 予算と貯金目標を決める | 予算・目標の設定 |
| Phase 2 発展 | 貯金で建設資金が入り、計画が消化される。技術による進化・悪い出来事 | 記録（貯金の確定）・債券・交換・修繕 |
| Phase 3 都市成熟 | 技術Lvで都市の姿が変わり、目標達成でシーズン終了 | 記録・観察 |

### 2.2 ゲーム内通貨

| 通貨 | 獲得 | 用途 |
|---|---|---|
| 金貨 G | 銀行からの時間配当 | 購入の精算。使わなかった分は記録で確定して債券・建設資金になる。建設資金への交換、像への積立、銀貨・債券への交換 |
| 銀貨 S | 購入記録・貯金記録・「今日は支出なし」・金貨からの交換 | 悪い出来事（火事）の修繕、建物の命名・装飾、タイムラプスの花火、債券を使ったときの手数料、交換の手数料 |
| 債券 | 確定した貯金・採掘の債券化・金貨からの交換・ユーザ通貨の余り | 購入の精算で足りない分の肩代わり（マイナス可）。持っている間は残高の 0.3%/日の利息が建設資金に入り、残高に応じた備えLvが悪い出来事を軽くする。債券に入った分のうち0以上・上限以内の分は、同じ額の建設資金も街に入る |
| ユーザ通貨 | 定義した発生ルール（毎分・周期・カレンダー指定日） | ジャンルが一致する購入の精算、債券への交換 |
| 建設資金（旧：都市資金） | 確定した貯金・債券化・金貨からの交換・債券の利息だけ（街は自分では稼がない） | 街の建設・アップグレード・進化・開拓 |

交換ルール：G→S は 1:1（無料。ゲーム内で使った金貨（貯金額）に加える）、G・ユーザ通貨→債券 は 1:1（無料。採掘・余りの債券化・確定した貯金も含め、債券が 0〜3M の範囲に入る分は、同じ額の建設資金も街に入る）、S→G・S→債券・S→建設資金・債券→他の通貨 不可。G→建設資金は 1G＝1円 ×（1 ＋ 銀行Lv・配当Lv・記録Lvのボーナス）、手数料 5S、ゲーム内で使った金貨（貯金額）に加える。シーズン最初の2週間は開拓期ボーナス（×2・×1.5）がつく。建設資金→通貨 不可。マイナスになり得るのは債券（と、林を押しのけて敷く道路の分の建設資金）だけ。

## 3. 特殊施設

### 3.1 銀行
- 目標・純増額・達成率を表示。達成率でレベルが決まる（0–19% Lv1 / 20% Lv2 / 40% Lv3 / 60% Lv4 / 80% Lv5 / 100% 完成）。
- レベルに応じて金貨の建設資金への交換効率ボーナス（+0/5/10/15/20/30%）。
- 達成率が下がるとレベルは再計算される。建物は消滅しない。技術Lvとは独立。
- 金貨の配当（3.2）と記録の報酬（3.3）も銀行の役割。以前の金鉱・銀鉱の建物は地図に置かず、既存の街からは読み込み時に取り除く（敷地は最初の土地用途に戻す）。未受取の配当は銀行の前の金貨の山で表す。
- 銀行のレベルは 銀行Lv（達成率）・配当Lv（3.2）・記録Lv（3.3）の3つで、金貨の交換効率のボーナスは足し合わせる（記録Lvのボーナスも金貨に足す。2026-11-07）。

### 3.2 金貨の配当（旧：金鉱）
- 採掘は月の収入の配当。毎分の採掘量 ＝ max(0, B − S − C) ÷ その収入期間の分数（月の収入を記録した期間は、雛形との差分の振り分け・減らしが加わる）。1分単位で採掘し、端数は内部で固定小数点（1G＝10⁶単位）で保持。回収できるのは整数部分。
- 月の境界・サブスクと毎分ルールの開始/終了時刻で採掘速度を区切って計算する（ユーザーのタイムゾーン基準）。
- 採掘のうち債券化率 r を債券へ直接入れる（上限 3M で停止）。債券がマイナスの間は max(r, 20%) を強制的に回す。債券化した分も配当Lvの累計に含める。
- タップで回収。複数端末から同じ金貨を二重回収できない。
- **記録による確定（2026-11-07）**：収支・貯金管理・誤差調整・「今日は支出なし」を記録すると、それまでの未回収の金貨（使わなかった配当）が貯金として確定し、債券（上限 3M まで。同じ額の建設資金つき）に入る。入りきらない分は建設資金になり、ゲーム内で使った金貨に数える。記録のない日の配当は、7日たつか、その日の収入期間が終わったら、推定の支出（直近28日の支出の記録の平均。記録が3件未満なら1日の配当の半分）を引いて自動で確定する。引いた分は未回収に残り、次の記録で確定する。
- 同じ収入期間に確定して債券に入れた分は、あとの購入で手数料なしで取り崩せる（使い過ぎに数えない）。超えた分は⑤のとおり。
- 購入の精算順：①像の積立金貨（紐付けた購入のみ） → ②ジャンルが一致するユーザ通貨（期限の近い順） → ③未回収金貨 → ④所持金貨 → ⑤債券（マイナス可）＋銀貨の手数料（使った債券の10%、上限50S。銀貨の不足分は債券から）。金貨・銀貨・ユーザ通貨はマイナスにしない。債券から払った額は月ごとに記録する（`MonthlyOverspend`）。過去の建物や資源は没収しない。
- 購入ごとに支払いの内訳を保存し、減額・削除は逆順（債券 → 所持金貨 → ユーザ通貨 → 像の積立金貨）で払い戻す。手数料は債券の支払い合計から計算し直す。
- 当月以外の日付の購入は家計履歴にのみ反映し、精算しない（締めた月を蒸し返さない）。
- レベルは累計回収金貨で決まり（0 / 5,000 / 15,000 / 40,000 / 80,000 / 150,000 G）、金貨の交換効率が上がる（+0〜20%）。採掘量は増えない。

### 3.3 収支記録（旧：銀鉱）
- 記録は **収入・支出・誤差調整** の3種類と、貯金管理（[record-input-redesign.md](record-input-redesign.md)）。
  - 収入：月の収入（未記録の期間を雛形で並べ、保存ボタンひとつ・一括保存。＋差分は振り分け、−差分は当期の未配当分 → 債券）、臨時の収入（全額を振り分け。初期値は即時貯蓄＝債券 → おまかせ交換）。
  - 支出：普通の支出（金額・日付・名称は必須、ジャンル・メモ任意）、サブスクの支払い・ほしい物の購入（設定から作ったベースを保存ボタンひとつで。ベースとの差は差分として解消）。
  - 誤差調整：手元のお金の推測（項目をチェックで足し引き、グラフつき、チェックは引き継ぐ）と実際の額の差を解消する。報酬なし。
  - 貯金管理：別口座への出し入れ（金額・日付・追加/引出・メモ）。1日3回まで。判定には使わない。
- 差分の解消：＋差分は債券へ上限まで（0〜上限の分は資源つき）、入りきらない分はおまかせ交換（手数料 5S、銀貨が足りなければなし）。−差分は全額を債券から（手数料：使った債券の10%、上限50S）。
- 登録した収支は金額だけ編集できる（変化分を差分として解消）。削除はなく、取り消しは金額0。
- 銀貨報酬：収入・支出 50S（月の収入は期間ごとに1回）、「今日は支出なし」50S（1日1回）、貯金管理 100S、誤差調整なし、1日 300S まで。金額に比例しない。同じ記録の報酬は1回だけ（編集・再送で再取得不可）。
- レベルは有効記録数で決まり（0/5/15/30/50/80件）、金貨（貯金）を建設資金にするときの効率が上がる（+0〜20%）。報酬量は増えない。
- 銀貨は建設資金に替えない。悪い出来事（火事）の修繕（100S）と手数料に使う（2026-11-07）。
- 銀貨は見た目にも使える（2026-11-07）：建物の命名（50S、12文字まで。外すのは無料）、建物の装飾（花壇・噴水・灯籠・祭りの旗のどれか1つ、150S。外すのは無料。2×2 以上の建物のそばに、建物の絵ごとに決めた位置で置く）、完了したシーズンのタイムラプスの花火（300S。進行中のシーズンの銀貨で払う）。どれも街の数値は変えない。
- 記録・金貨回収・G→S 交換は無料。

### 3.4 公園（サブスク）
- サブスク1件＝公園1つ。月額に応じて面積（装飾段階）が決まる。月額は採掘から差し引かれる。
- 解約すると閉園状態になる（取り壊しは任意）。
- 幸福度効果は逓減する（1つ目+6、以降は前の0.6倍、合計上限+15）。高額サブスクを契約しなくても街は十分発展する。
- 年額は ÷12 で月額換算。支払いは収支記録の「支出」に期間ごとに並び、登録額のまま保存すれば精算しない（二重計上の防止）。請求額との差は差分として解消する。

### 3.5 像（ほしい物）
- 登録すると像の建築計画が生成される。価格で 銅像（〜4,999円）/ 銀像（〜29,999円）/ 金像（30,000円〜）。
- 金貨を任意に分割投入。投入金貨は「積立済み金貨」として予約され、資源交換に使えない。購入前なら取消で返却。
- 進捗＝積立額÷価格。100%で資金準備完了。購入を記録すると完成し、積立金貨は価格の精算に充当する（二重計上なし）。価格より安く買えた分は＋差分、高かった分は−差分として解消する。
- 街の発展で建て替えない。像・公園は街の発展で撤去しない。

### 3.6 貯金額と欲しいもの貯金の表示

ホーム・銀行画面に2種類の貯金を並べて表示する。

| 表示 | 内容 | 増える時 | 減る時 |
|---|---|---|---|
| 貯金目標 | 貯金額 ＝ ゲーム内で使った金貨（塗り）＋ 債券（斜線。マイナスなら減らし、全体は0未満にしない） | 金貨で建設資金を得た時・確定で債券に入りきらなかった時／債券の増加（確定・交換・債券化・＋差分） | 債券を現実の支払いに使った時（精算・−差分） |
| 欲しいもの貯金 | 未購入のほしい物への積立金貨 ÷ その合計価格 | 像への積立 | 積立の取消・購入記録での充当 |

- 金貨はゲーム内で使っても現実のお金は出ていかないため、ゲーム内で使った額（1G＝1円。建設資金・銀貨への交換、確定で債券に入りきらず建設資金にした分）はそのまま貯金になる。銀貨払いの交換・像の積立は対象外（金貨→銀貨で数えた分を銀貨の使い道で二重に数えない）。債券化の資源は債券で数えるので二重に数えない。
- 貯金額は技術Lv（最高到達額）・銀行Lv・目標到達（GOAL_REACHED）の判定と表示の両方に使う。貯金管理の記録では変わらない。
- 貯金額はシーズンごとにリセットする。

## 4. 街のシステム

### 4.1 建物の系統と段階

建物は「系統」に属し、技術Lvと発展Lvの **両方** を満たすと次の段階に進化できる（D-3）。

| 系統 | 段階（必要 技術Lv / 発展Lv） |
|---|---|
| 住宅 | 小屋(1/1) → 木造住宅(2/1) → レンガ住宅(3/2) → 集合住宅(4/3) → マンション(4/4) → 高層住宅(5/5) |
| 農業 | 畑(1/1) → 農場(2/1) → 機械化農場(3/2) → 大規模農場(4/3) → 自動農場(6/5) |
| 木材 | 木材加工所(1/1) |
| 石材 | 石材加工所(2/2) |
| 工業 | 工房(2/2) → 工場(3/2) → 大規模工場(4/4) → 自動化工場(6/5) |
| 商業 | 屋台(1/2) → 小売店(2/2) → 市場(3/3) → 商業施設(4/4) → 百貨店(5/5) |
| オフィス | オフィスビル(5/4) → 商業タワー(7/6) |
| 道路 | 未舗装道路(1/1) → 舗装道路(3/2) → 幹線道路(4/3) → 高度交通網(6/5) |
| 電力 | 発電所(3/2) → 高効率発電所(5/4) → 先進エネルギー施設(6/5) |
| 鉄道 | 鉄道駅(4/4) |
| 物流 | 物流センター(5/4) |
| 教育 | 学校(4/3) → 大学(5/4) → 研究所(6/5) |
| 医療 | 病院(4/3) |
| 文化 | 図書館(4/3) → 文化施設(5/4) |
| 未来 | 未来都市センター(7/6) |

- 建物Lv（1〜上限）は段階とは独立。上限は発展Lvで上がる（Lv1–3：3、Lv4：4、Lv5：5、Lv6：6）＝高密度化。
- 建物Lv倍率 ＝ 1 + 0.25 ×（Lv − 1）。
- 生産式：`実生産 = 基本生産 × 建物Lv倍率 × 技術倍率 × 労働充足率 × 電力充足率 × 物流効率`
- 技術倍率（技術Lv1〜7）：1.0 / 1.1 / 1.25 / 1.4 / 1.6 / 1.8 / 2.0。公共施設の **技術活用率**（70%〜100%）で倍率の上乗せ分の発揮度が決まる（D-1）。
- 食料と、電力需要0の基礎建物は電力なしで稼働する。

### 4.2 街の経済（2026-11-07 改訂）

**貯金 → 建設資金 → 計画の消化（建設）→ 住宅・仕事 → 人口・幸福度（賑わい）**

- 街は自分では稼がない。税収・商業・工業の収益はなく、建設資金は貯金（確定した配当・債券化・金貨からの交換）と債券の利息だけから入る。
- 計画の値段（円）＝ カタログの相対コスト × 基準額 × κ（0.0002）×（1 − 割引）。基準額は月間自由予算と目標額の小さいほうで、シーズン開始時に決める。
- 人口は住宅の空きのうち1時間に25%ずつ移り住んで増える（食料が足りない間は遅くなる）。人口と幸福度は街の賑わいの表示と悪い出来事の被害の大きさにだけ使う。
- 木材加工所・石材加工所・工場は建設費の割引の施設（1棟 −2%、合計 −40% まで）。
- 資源は負にならない。不足時は生産効率が落ちるだけで、建物は壊れない。
- 目安（M＝10万円、毎月 M の20%を貯め、初日に5,000円）：町（Lv3）が2日目、地方都市（Lv4）が19日目、巨大都市（Lv6）が5か月前後（`scripts/balance.ts` で確認。[savings-driven-growth.md](savings-driven-growth.md) §12）。

### 4.3 街の発展

一定間隔（10分）ごとに以下を実行する。

1. 資源・需要を評価する。
2. 決まった順（すべての街で同じ。設定で変えられない）に従って「必要事項」の候補を並べる（計画列）。
   1. 食料・電力の不足解消（電力を先にし、電力が足りない間は電力を使う段階への農場の進化をしない。働き手が足りない間は農場を増やさず住宅を先にする）
   2. 新産業への投資（未建設の解放済み系統。系統ごとに1棟目だけ）
   3. 雇用不足の解消（仕事＜労働力）
   4. 住宅不足の解消（空きが15%未満）
   5. 物流の改善（物流効率＜90%）
   6. 生産効率の改善（技術進化・建物Lvアップ）
   7. 景観改善
3. 計画列を先頭から建設資金で消化する。先頭の計画が払えなければ **そこで止めて貯める**（後ろの安い計画に回さない）。
4. 払えれば建設ジョブを作成する（建設時間あり）。同時に進める工事は発展Lvごとに 3 / 4 / 6 / 8 / 12 / 16 件まで（何が足りないかは工事中の分も完成したものとして判断する）。台風の間は工事を始めない。
5. 公園・像・特殊施設には手を出さない。

技術Lvが上がっても既存建物は一瞬で置き換わらず、資金と時間を使って **1棟ずつ** 進化する。

開発計画は**計画列**として無限に続く：上の優先順の候補のあとに、解放済みの新築のうち最も高いものと同じコストの**拡張計画**が並ぶ（拡張計画は着工しない備蓄目標）。在庫を計画列の先頭から割り当てて最初に足りなくなった計画の不足分（木材・石材）と、食料の24時間分の不足分を**必要資源**とし、おまかせ交換・債券化の資源の割合に使う（[needs-based-exchange.md](needs-based-exchange.md) §4）。

### 4.4 プレイヤーと街の発展

街の建設・アップグレード・進化・区画の開拓は、4.3 の手順だけで進む（2026-11-05 に手動開発と即時完了を廃止）。プレイヤーは街の開発に直接手を出さず、「自動開発」という仕組みも画面には出さない。プレイヤーが街に関わるのは、**記録（貯金の確定）・債券・金貨の交換**と、火事で休業した建物の **銀貨での修繕** で、これが発展の資金と街の守りになる（2026-11-07）。見た目だけは、銀貨で建物に名前をつけ、装飾を添えられる。

### 4.5 発展度

- 発展pt ＝ 完成した計画の累計額 ÷ 基準額 × 1000（2026-11-07 改訂。時間で増える発展pt・債券倍率・稼働係数は廃止）。
- 発展Lv：Lv1 0 / Lv2 30 / Lv3 120 / Lv4 300 / Lv5 700 / Lv6 1,500 pt（基準額の 0.03 / 0.12 / 0.3 / 0.7 / 1.5 倍の工事。集落→村→町→地方都市→大都市→巨大都市）。Lv6 からは発展ptで開拓できる区画が増える。
- 開拓期ボーナス：シーズン開始1〜7日目の貯金は ×2、8〜14日目は ×1.5 の建設資金になる（増える分は基準額の0.3倍まで）。

### 4.6 技術Lv

| 技術Lv | 貯金額の最高到達額（基準額の倍数） | 基準額10万円の例 | 解放内容 |
|---|---:|---:|---|
| 1 | 0 | 0円 | 集落・農業 |
| 2 | 0.05 | 5,000円 | 基本産業・建物の自動増築 |
| 3 | 0.15 | 15,000円 | 工業化・発電・工場 |
| 4 | 0.3 | 30,000円 | 教育・研究・都市交通 |
| 5 | 0.6 | 60,000円 | 高度商業・オフィス・高層建築 |
| 6 | 1.0 | 100,000円 | 自動化産業・先進インフラ |
| 7 | 1.5 | 150,000円 | 未来都市・先端技術 |

- 発展度・通貨・時間では上がらない。購入記録でも上がらない。
- 技術解放で発展ポイントを直接付与しない。
- 貯金目標が小さければ全技術を解放せずにシーズン完了できる。

### 4.7 マップと土地用途

- 土地用途：住宅・商業・工業・農業・公共・特殊・未指定。初期は標準的な用途配置を提案し、プレイヤーが塗り替えられる。
- マップ（[map-layout-redesign.md](map-layout-redesign.md)）：銀行の中心を原点にした大きさを仮定しないマップ。初期は中心の 10×10 で、資源を使って 5×5 の区画ごとに開拓する（開拓できる区画数の上限は発展Lvで決まる）。建物の大きさは道路・像が 1×1、銀行と高額なサブスクの公園が 3×3、それ以外が 2×2。道路以外の建物は、銀行まで道路でつながった道路に接すること。
- 自動配置：用途が一致する土地 → 未指定の土地の順。同用途の隣接・道路の隣接を加点、住宅と工業の隣接を減点。

### 4.8 放置計算

- サーバーで常時計算しない。アクセス・記録・建物操作・交換・サブスク変更の時に、最終計算時刻から現在まで再計算する。
- 10分刻みの **絶対時刻に揃えたティック** で進める。いつアクセスしても同じ経過時間なら同じ結果になり（決定的）、同じ時間を二重計上しない。
- 債券化・確定・利息が街の建設資金になるため、ティックごとに「金貨の配当（債券化含む）→ ユーザ通貨の発生・期限 → 記録のない日の自動の確定 → 債券化の建設資金・債券の利息 → 街の1ティック（休業の再開・悪い出来事・工事の完了・人口・計画の消化）」を繰り返す。最後の端数は配当・ユーザ通貨だけ進める。
- 再訪時（前回から1時間以上）に「前回から◯時間」の変化（人口・建設・アップグレード・発展pt・建設資金・確定した貯金・債券の利息・悪い出来事）を表示し、変化したマスをハイライトする。

### 4.9 悪い出来事（2026-11-07）

- 発展Lv2 以降、平均 約8日に1回（シーズン開始から3日間は起きない）。起きる日時と種類はシーズンの開始時刻と日付から決定的に決める。
- 台風（工事が12時間止まる）・不作（食料生産 −50%、48時間）・火事（建物が休業し、銀貨100Sで修繕するか72時間で再開）・資材の値上がり（値段 +30%、24時間）・停電（電力 −50%、24時間）。建物は壊さず、人口も減らさない。
- 備えLv1 で被害の時間と割合が半分、Lv2 で台風と値上がりを防ぐ、Lv3 で火事を建設資金からすぐ修繕、Lv4 ですべて防ぐ。幸福度70以上なら被害 −25%、40未満なら +25%。火事は人口1,000人ごとに1棟増える（最大3棟）。
- 備えLvごとに銀行のそば（特殊地区。銀行に隠れない手前の角から）に施設が建つ：Lv1 防災倉庫、Lv2 消防署、Lv3 避難公園、Lv4 銀行の金庫。1×1 の特殊施設で、街の数値は変えない。備えLvが下がると壊さずに閉め（暗く描く）、戻ると再開する。

## 5. シーズン

- 状態：ACTIVE（進行中）→ GOAL_REACHED（達成率100%以上・確認待ち）→ COMPLETED（完了・アーカイブ）。同時に1つのみ。
- 達成率が100%に達すると達成画面を出し、「目標を完了する」で確定する（誤入力対策）。確認待ちの間も操作できる。引出で100%を下回れば ACTIVE に戻る。
- 完了時：街の状態を保存、イベント履歴を確定、建築・通貨操作を停止、タイムラプスを解放、アーカイブ。完了した街は再編集不可（タイムラプス再生のみ）。
- 新シーズン：街・資源・通貨（債券はマイナスも0に、ユーザ通貨の残高も0に）・施設Lv・像の進捗・貯金純増額・発展度・技術Lv・建設資金をリセット。基準額は新シーズン開始時の月間自由予算と目標額で決め直す。アカウント・家計履歴・予算・サブスク・ほしい物（未購入分）・ユーザ通貨の定義・ジャンル・債券化率・過去のタイムラプスは引き継ぐ。金貨は新シーズン開始後の時間のみ配当する。

街の状態を1行にまとめるのは、放置計算で全建物を一括更新するためと、1ユーザーの操作を1トランザクションで直列化するため。

### 9.2 ルール
- 現実の金額は円の整数。配当の端数は 10⁻⁶G 単位の整数。
- 通貨の増減は台帳で管理。すべての記録に一意ID。報酬は記録IDで1回のみ。
- 同一ユーザーの操作はトランザクション内でユーザー単位のロックを取り直列化する。`Idempotency-Key` ヘッダーによる再送防止。
- 時間計算はサーバー時刻が基準（端末の時計変更は無効）。
- 完了したシーズンのゲーム履歴は変更不可。
