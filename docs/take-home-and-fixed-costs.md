## 1. 目的

設定で入れる「月間自由予算」は、手取りから固定費と予定貯金を自分で引いた額である。口座には手取りの全額が入り、固定費が出ていくので、置き場所の残高を合わせるために、給料のうち自由予算でない分と固定費の引き落としを「予算外の入出金」として手で記録している。

本書では、設定で入れる額を**手取り月収**に変え、**固定費**を登録して、自由予算を「手取り月収 − 固定費」で自動で出す。給料は振り込まれた額のまま月の収入になり、固定費の引き落としは登録から作った行を保存するだけになる。予算外の入出金は用途がなくなるので、なくす。

債券の上限・備えLv・基準額の物差し（M）は、自由予算ではなく手取り月収にする。固定費を登録しても M は下がらない。

## 2. As-Is（今の作り）

- 設定と開始画面で入れるのは **月間自由予算 B**（固定費・予定貯金を除いた自由に使える額。`User.monthlyBudget`）。
- 金貨の配当（月）は max(0, B − S − C)。S はサブスクの月額換算の合計、C はユーザ通貨の発生額。
- M（月に使えるお金）＝ B。債券の上限（3M）、備えLv（0.5 / 1 / 2 / 3 か月分）、持ち込みの備えの上限（3M）、基準額（M と目標額の小さいほう）に使う。
- 月の収入の雛形の金額は B。記録すると入金先の残高に B が入る。
- 手取りのうち B でない分の入金と、家賃・固定費の出金は、**予算外の入出金**（`OutsideRecord`）として手で記録する。置き場所の残高だけを動かし、ゲームには使わない。記録しないと、照合の誤差として債券に入る（＋）か、債券から手数料つきで引かれる（−）。
- サブスクは月額を配当から引き、支払いの行が支出タブに並ぶ。1件ごとに公園が建つ（月 3,000円以上は 3×3）。
- 先取り貯金（予定貯金）は B の外。貯金用の置き場所への振替で記録し、街の貯金には数えない。

| # | 問題 |
|---|---|
| P1 | 自由予算を自分で計算して入れる必要がある（手取り − 固定費 − 予定貯金）。固定費が変わるたびに計算し直す |
| P2 | 給料の入金が2件の記録になる（月の収入 B と、予算外の入金）。振込額とアプリの「月収」が合わない |
| P3 | 固定費の引き落としを毎回、名前・金額・置き場所から手で入れる。報酬もない。忘れると照合の誤差として債券が動く |
| P4 | 固定費にいくらかかっているかが、アプリでわからない |
| P5 | 先取り貯金は貯めているのに、街が育たない |

## 3. 用語

### 3.1 記号と式

```
手取り月収 M                      設定で入れる。債券の上限（3M）・備えLv・基準額の物差し
月間固定費 F                      登録した固定費の月額換算の合計（自動）
自由予算   B ＝ max(0, M − F)     自動。金貨の配当の元
金貨の配当（月）＝ max(0, B − S − C)   式は今と同じ
```

> 例：M ＝ 250,000。固定費は 家賃 80,000・光熱費 15,000・通信費 8,000・保険 12,000・奨学金 5,000 で F ＝ 120,000。B ＝ 130,000。S ＝ 3,000、C ＝ 40,000 なら金貨の配当は月 87,000G。債券の上限は 750,000（3M）。

## 5. 固定費

### 5.1 固定費とサブスク

固定費は、生活のために毎月（または毎年）決まって出ていくお金である。家賃・住宅ローン・光熱費・通信費・保険・奨学金の返済・税金・定期代など。手取り月収から先に引き、残りを自由予算にする。

| | 固定費 | サブスク |
|---|---|---|
| 例 | 家賃・光熱費・通信費・保険・ローン | 動画配信・音楽・ジム・アプリ |
| 自由予算 | 外（M から引いて B を出す） | 内訳（B から引いて配当を出す） |
| 金貨の配当 | 月額の分だけ減る | 月額の分だけ減る（今と同じ） |
| M（債券の上限・備えLv・基準額） | 下げない | 下げない（今と同じ） |
| 公園 | 建たない | 1件ごとに建つ（今と同じ） |
| 支払いの記録 | 支出タブの行を保存する。登録額は精算せず、差は差分として解消する | 同じ（今と同じ） |

### 5.2 登録

| ID | 要件 |
|---|---|
| FC-01 | 「固定費・サブスク」の画面（SCR-06）で、固定費を登録・編集・削除できる。項目はサブスクと同じ（名前・金額・周期（毎月 / 毎年）・開始日・終了日・出どころ・メモ）に **支払日** を足す（FC-12） |
| FC-02 | 種類（固定費 / サブスク）は登録するときに選び、あとから変えられる。サブスクを固定費に変えると公園はなくなり（サブスクの削除と同じ）、固定費をサブスクに変えると公園が建つ |
| FC-03 | 月間固定費 F ＝ その時点で有効な固定費（開始日〜終了日）の月額換算の合計。年額は ÷12（サブスクと同じ） |
| FC-04 | 固定費は現実の契約の記録なので、F が M を超えても、B − S − C が負になっても保存を拒否しない（サブスクと同じ。設計原則5）。超える月があれば警告し、その月の自由予算と配当は 0 になる |
| FC-05 | 登録・変更・削除は、今この時点からの自由予算・配当に反映する（サブスクと同じ）。過去の配当は変えない |
| FC-06 | 月によって額が変わる固定費（光熱費など）は、目安の額を登録する。実際の額との差は、支払いの記録のときに差分として解消する（FC-13） |
| FC-07 | 引き落とし・支払いの単位で1件ずつ登録するのを基本にする。まとめた1件でも登録できる（支払いの記録も期間ごとに1件にまとまる） |
| FC-08 | 登録していない置き場所への積立（iDeCo・積立NISA・財形・貯蓄型の保険など）は、固定費として登録できる。街の貯金には数えない。貯金用の置き場所への積立は振替で記録し、固定費にはしない（§6.3） |
| FC-09 | 固定費は公園を建てず、幸福度も変えない。街には金貨の配当を通してだけ影響する。M（債券の上限・備えLv・基準額）は下げない（FB-02） |
| FC-10 | 固定費の定義はシーズンをまたいで引き継ぐ（サブスクと同じ） |

### 5.3 支払いの記録

| ID | 要件 |
|---|---|
| FC-11 | 登録済みの固定費から、未記録の支払いを支出タブの上段に並べる（サブスクの行と同じ形：`11月 家賃 80,000円 [保存]`・[一括保存]）。月額は毎期間、年額は開始日と同じ月日がある期間（今のサブスクと同じ） |
| FC-12 | **支払日**（1〜31、任意。その月にない日は末日）を入れた月額の固定費・サブスクは、**その日が来てから**行を出し、日付の初期値をその日にする。入れなければ今と同じ（期間の初めから並べる）。シーズンの開始日・その固定費の開始日より前の支払日の分は並べない |
| FC-13 | 記録は支出（固定費の支払い）として保存し、固定費と期間に紐付ける。同じ固定費・同じ期間は1件だけ。登録額の分は精算しない（M から先に引いている）。請求額 ＜ 登録額 は ＋差分、請求額 ＞ 登録額 は −差分として、サブスクと同じルールで解消する（[record-input-redesign.md](record-input-redesign.md) EX-03・EX-04） |
| FC-14 | 出どころの初期値は、固定費に登録した置き場所（サブスクと同じ。RS-03）。クレカ払いの固定費は出どころをクレカにする（引き落とし予定に入る） |
| FC-15 | 行は「この回は記録しない」で消せる（開始前に払った分、置き場所の開始残高にもう入っている分）。消した回はもう並べず、残高も通貨も動かさない。サブスクの行にも置く |
| FC-16 | 報酬は支出の記録と同じ 50S（1件1回、1日 300S の上限の中）。記録による貯金の確定（REC-01）も同じに起きる。自動の確定で引く推定の支出には数えない（サブスクと同じ） |
| FC-17 | 差分が続いたら「登録額を変更しますか」と案内する（EX-05 と同じ） |
| FC-18 | 照合（残高を合わせる）の画面で、当期までの未記録の固定費・サブスクの行があるとき、「未記録の固定費・サブスクの支払いがあります。先に保存してください」と出す（照合はできる。引き落とし予定の CB-06 と同じ） |

> FC-18 の理由：固定費は配当からもう引いている。支払いを記録しないまま照合すると、引き落とされた額が誤差として債券からも引かれ、二重になる。
>
> 例（収入日 25日、家賃 80,000円・支払日 27日・出どころ 口座A）：10/27 から支出タブに「10月 家賃 80,000円 [保存]」が出る。保存すると口座A が 80,000円減り、金貨・債券は動かず、50S が入る。
>
> 例（電気代：登録額 8,000円）：請求が 9,500円なら −差分 1,500 を債券から（手数料あり）、6,800円なら ＋差分 1,200 が債券に入る。

### 6.2 ゲームバランスの変化

M が今の自由予算から手取り月収に変わるので、同じ人でも M が大きくなる。M にかける倍率と閾値（3M、0.5 / 1 / 2 / 3 か月分、基準額の倍数、値段の係数）は本書では変えない。

> 例：手取り 250,000、固定費 120,000、先取り貯金 30,000 の人。

| | 今 | 変更後 |
|---|---:|---:|
| M | 100,000（月間自由予算） | 250,000（手取り月収） |
| 自由予算（配当の元） | 100,000 | 130,000 |
| 債券の上限・持ち込みの備えの上限（3M） | 300,000 | 750,000 |
| 備えLv1 / 2 / 3 / 4 になる額 | 50,000 / 100,000 / 200,000 / 300,000 | 125,000 / 250,000 / 500,000 / 750,000 |
| 債券の利息の上限（3M の 0.3%/日） | 900円/日 | 2,250円/日 |
| 基準額（目標額が 250,000 以上のとき） | 100,000 | 250,000 |
| 技術Lv7 になる貯金額（基準額の 1.5倍） | 150,000 | 375,000 |

- 計画の値段、開拓費、発展Lv・技術Lv の閾値、開拓期ボーナスの上限は基準額に比例するので、上の例では 2.5倍になる。同じ額を貯めたときの街の発展と備えLv は、その分だけ遅くなる。
- 目標額が今の自由予算より小さいシーズンは、基準額が目標額のままなので、値段と閾値は変わらない（債券の上限と備えLv は変わる）。
- 先取り貯金が街の貯金に数えられるようになるので（§6.3）、街に入る貯金の額は増える。
- [requirements.md](requirements.md) §4.2 の目安（M の 20% を毎月貯める人）は、手取りの 20% を貯める人の目安になる。上の例では月 50,000円（先取り貯金 30,000 ＋ 使い残し 20,000）にあたる。
- 実装のときに、`scripts/balance.ts` の M を手取り月収として読み替え、目安と悪い出来事の被害（備えLv が上がるまでの期間）を確かめる。

| R2 | 先取り貯金 | 自由予算に含め、使わなかった配当として街の貯金に数える（§6.3） | 自由予算 ＝ M − F の定義からそうなる。貯めた分だけ街が育つ |
| R3 | 固定費が手取り月収・自由予算を超えるとき | 拒否せず警告だけ（FC-04） | 現実の契約の記録を妨げない（設計原則5。サブスクと同じ） |
| R4 | 支払日 | 任意で持ち、サブスクにも使える（FC-12） | 引き落とし前に記録すると、その間の残高が実際と合わない |
| R5 | 開始前に払った分の行 | 「この回は記録しない」で消せる（FC-15） | 置き場所の開始残高にもう入っている |
| R6 | 未記録の固定費があるときの照合 | 注意を出す（FC-18） | 配当と債券で二重に引かれるのを防ぐ |
| R7 | 記号 | 手取り月収 M・月間固定費 F・自由予算 B | 今の「3M」「B − S − C」の式をそのまま使える |
| R8 | 予算外の入出金をなくしたあとの立替・貸し借り・預かり金 | 支出と臨時の収入で記録する（OM-03） | 専用の記録を持たずに、置き場所の残高を合わせられる |
