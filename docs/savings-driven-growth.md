## 1. 目的

次の4つの体験を、ゲームの中心に置く。

| ID | 体験 | 目安 |
|---|---|---|
| E-1 | お金を貯めると、街が目覚ましく発展する | 入金のたびに工事が一斉に始まり、数時間〜数日で形になる。貯金のない期間は街が止まる |
| E-2 | 序盤に貯めるほど、発展が目覚ましい | 初日に 0.05M（M＝月間自由予算。10万円なら5,000円）入れると、2日目に町になる |
| E-3 | 債券（もしもの備え）を用意しておくと得をする | 債券から毎日建設資金が入り、悪い出来事から街を守る |
| E-4 | こまめに記録すると、何かと便利 | 記録した日の貯金はすぐ街に入り、先の見通しが出て、修繕に使う銀貨が貯まる |

## 3. As-Is（現状）

[game-balance-review.md](game-balance-review.md) の試算（交換なしの放置60日）による。

- **街が自分で稼ぎすぎる**：街の都市資金収入は60日で約2,000倍になり、16日目以降はプレイヤーの金貨（1日1,000円と仮定）を上回る（B-04）。
- **お金を入れても街が使い切れない**：発展ptが時間で決まり、序盤の入金は発展Lv・建設時間・区画の上限で止まる。累計20万円を全額入れても、60日目の人口は入れない場合とほぼ同じだった（3,053人と3,090人）。
- **債券の効きが見えない**：債券倍率 k は時間発展の発展ptにしか掛からず、発展Lv6（17日目）以降は街に効かない（B-05）。
- **記録の見返りが小さい**：銀貨の記録報酬（1日最大300S）は、5日目に街の収入の約47%、20日目に約1.5%まで下がる（B-11）。
- **資源が多すぎる**：木材・石材・食料・都市資金の4種類があり、おまかせ交換が1種類に偏る（B-03）。木材・石材は中盤から大量に余る（B-08）。

## 4. To-Be：全体像

```
現実の貯金（使わなかった金貨・債券への振り分け）
  └→ 記録で確定（未記録の日は7日後に自動確定）            … §9
       └→ 債券（上限 3M まで自動）＋ 同額の建設資金          … §8
            ├→ 債券の利息：毎日、建設資金が入る              … §8
            └→ 建設資金 × 開拓期ボーナス × 記録Lvボーナス     … §7・§9
                 └→ 計画列を先頭から消化（同時工事数まで）     … §5
                      └→ 完成した計画の累計 → 発展Lv           … §6
悪い出来事 → 工事の遅れ・休業（壊さない）← 債券の備えLvで軽減 … §10
```

街はプレイヤーのお金でしか発展しない。そのかわり、入れたお金は必ず目に見える工事になる。時間がするのは工事を進めることだけで、「放っておいても育つ」は「貯めた分は、放っておいても形になる」に変わる。

## 5. To-Be：成長の源泉（計画の消化）

| ID | 要件 |
|---|---|
| GRW-01 | 税収・商業・工業の都市資金収入をなくす。街の建設資金は貯金（§8・§9）からだけ入る |
| GRW-02 | 木材・石材・都市資金を **建設資金**（金貨建て、1G＝1円）の1種類にまとめる。木材・石材は在庫や交換の対象から外し、建物の見た目（素材）にだけ残す。食料は街の中だけで回る（農場が作り、住民が食べる）。お金では買わない |
| GRW-03 | 街は計画列（NX-01）を先頭から建設資金で消化する。同時に進める工事は発展Lvごとに 3 / 4 / 6 / 8 / 12 / 16 件まで。大きな入金は数時間〜数日かけて形になる |
| GRW-04 | 発展Lvは **完成した計画の累計額**（基準額の倍数、§6）で決める。時間で増える発展pt（`DEV_PER_HOUR`）・稼働係数・人口の節目による発展ptは廃止する |
| GRW-05 | 木材加工所・石材加工所・工場は「建設費の割引」の施設にする（例：1棟あたり −2%、合計 −40% まで）。街が育つほど、同じ貯金で多く建てられる |
| GRW-06 | 建設資金がなければ新しい工事は始まらない。工事中の分は完成させる。住民は暮らし続け、建物も人口も減らさない（設計原則4） |
| GRW-07 | 計画列の優先順は「不足の解消 → 新産業 → 雇用 → 住宅 → 物流 → 生産効率 → 景観」にする（B-01・R-01。新産業は系統ごとに1棟目だけなので、ほかを長く待たせない）。不足の解消では電力を食料より先にし、電力が足りない間は電力を使う段階への農場の進化をしない（B-02・R-02）。働き手が足りない間は農場を増やさず、住宅を先にする |
| GRW-08 | 人口と幸福度は、街の賑わいの表示と悪い出来事の被害の大きさ（EVT-07）にだけ使う。建設資金・発展Lv・計画の値段には影響しない。雇用・商業・公共施設・公園は幸福度の計算にだけ使う |
| GRW-09 | 人口は時間で増えるのではなく、住宅の空きのうち1時間に25%ずつ移り住んで埋まる（食料が足りない間は遅くなる）。時間で決まる人口の伸び（`POP_GROWTH_*`）は使わない。人口の伸びを待って住宅や雇用の計画が止まり、入金を使い切れなくなるのを防ぐ |

実装で決めた細部：

- **確定する額**：記録したときは、未回収の金貨（それまでの配当から、記録した支出を払った残り）をすべて確定する。所持金貨（「受け取る」で手元に移した分）は確定しない。
- **同じ期間の取り崩し**：同じ収入期間に確定して債券に入れた額までは、あとの購入で債券から払っても手数料をとらず、使い過ぎ（`MonthlyOverspend`）にも数えない（`settle.ts` `pay` の `draw`）。月の途中に確定した分を月末の買い物で使っても損をしないようにするため。払い戻すと、また手数料なしで取り崩せる。
- **推定の支出**：直近28日の支出の記録（サブスクを除く）の合計 ÷ 28。記録が3件未満なら、1日の配当の半分とみなす（`config.ts` `SPEND_ESTIMATE_*`）。差し引いた分は未回収に残り、次に記録したときに、実際の支出を払ったあとで確定する。
- **悪い出来事の種**：シーズンの開始時刻と日付から決める。人口は減らさない（休業した住宅の分も）。
