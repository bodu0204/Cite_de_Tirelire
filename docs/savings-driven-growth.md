## 1. 目的

次の4つの体験を、ゲームの中心に置く。

| ID | 体験 | 目安 |
|---|---|---|
| E-1 | お金を貯めると、街が目覚ましく発展する | 入金のたびに工事が一斉に始まり、数時間〜数日で形になる。貯金のない期間は街が止まる |
| E-2 | 序盤に貯めるほど、発展が目覚ましい | 初日に 0.05M（M＝月間自由予算。10万円なら5,000円）入れると、2日目に町になる |
| E-3 | 債券（もしもの備え）を用意しておくと得をする | 債券から毎日建設資金が入り、悪い出来事から街を守る |
| E-4 | こまめに記録すると、何かと便利 | 記録した日の貯金はすぐ街に入り、先の見通しが出て、修繕に使う銀貨が貯まる |

## 3. As-Is（現状）

[game-balance-review.md](game-balance-review.md) の試算（交換なしの放置60日）による。

- **街が自分で稼ぎすぎる**：街の都市資金収入は60日で約2,000倍になり、16日目以降はプレイヤーの金貨（1日1,000円と仮定）を上回る（B-04）。
- **お金を入れても街が使い切れない**：発展ptが時間で決まり、序盤の入金は発展Lv・建設時間・区画の上限で止まる。累計20万円を全額入れても、60日目の人口は入れない場合とほぼ同じだった（3,053人と3,090人）。
- **債券の効きが見えない**：債券倍率 k は時間発展の発展ptにしか掛からず、発展Lv6（17日目）以降は街に効かない（B-05）。
- **記録の見返りが小さい**：銀貨の記録報酬（1日最大300S）は、5日目に街の収入の約47%、20日目に約1.5%まで下がる（B-11）。
- **資源が多すぎる**：木材・石材・食料・都市資金の4種類があり、おまかせ交換が1種類に偏る（B-03）。木材・石材は中盤から大量に余る（B-08）。

## 4. To-Be：全体像

```
現実の貯金（使わなかった金貨・債券への振り分け）
  └→ 記録で確定（未記録の日は7日後に自動確定）            … §9
       └→ 債券（上限 3M まで自動）＋ 同額の建設資金          … §8
            ├→ 債券の利息：毎日、建設資金が入る              … §8
            └→ 建設資金 × 開拓期ボーナス × 記録Lvボーナス     … §7・§9
                 └→ 計画列を先頭から消化（同時工事数まで）     … §5
                      └→ 完成した計画の累計 → 発展Lv           … §6
悪い出来事 → 工事の遅れ・休業（壊さない）← 債券の備えLvで軽減 … §10
```

街はプレイヤーのお金でしか発展しない。そのかわり、入れたお金は必ず目に見える工事になる。時間がするのは工事を進めることだけで、「放っておいても育つ」は「貯めた分は、放っておいても形になる」に変わる。

## 5. To-Be：成長の源泉（計画の消化）

| ID | 要件 |
|---|---|
| GRW-01 | 税収・商業・工業の都市資金収入をなくす。街の建設資金は貯金（§8・§9）からだけ入る |
| GRW-02 | 木材・石材・都市資金を **建設資金**（金貨建て、1G＝1円）の1種類にまとめる。木材・石材は在庫や交換の対象から外し、建物の見た目（素材）にだけ残す。食料は街の中だけで回る（農場が作り、住民が食べる）。お金では買わない |
| GRW-03 | 街は計画列（NX-01）を先頭から建設資金で消化する。同時に進める工事は発展Lvごとに 3 / 4 / 6 / 8 / 12 / 16 件まで。大きな入金は数時間〜数日かけて形になる |
| GRW-04 | 発展Lvは **完成した計画の累計額**（基準額の倍数、§6）で決める。時間で増える発展pt（`DEV_PER_HOUR`）・稼働係数・人口の節目による発展ptは廃止する |
| GRW-05 | 木材加工所・石材加工所・工場は「建設費の割引」の施設にする（例：1棟あたり −2%、合計 −40% まで）。街が育つほど、同じ貯金で多く建てられる |
| GRW-06 | 建設資金がなければ新しい工事は始まらない。工事中の分は完成させる。住民は暮らし続け、建物も人口も減らさない（設計原則4） |
| GRW-07 | 計画列の優先順は、新産業を生産効率の前にする（B-01・R-01）。不足の解消では電力を食料より先にする（B-02・R-02） |
| GRW-08 | 人口と幸福度は、街の賑わいの表示と悪い出来事の被害の大きさ（EVT-07）にだけ使う。建設資金・発展Lv・計画の値段には影響しない。雇用・商業・公共施設・公園は幸福度の計算にだけ使う |

## 8. To-Be：債券（もしもの備え）を持つ得

| ID | 要件 |
|---|---|
| RSV-01 | 確定した貯金は、債券が上限（3M）に届くまで自動で債券に入る。入った額と同じ建設資金が街に入る（現行の「債券に入った分に資源をつける」を建設資金にしたもの）。上限を超える分は建設資金だけになる |
| RSV-02 | **利息**：毎日、債券残高（0〜3M）の 0.3% を建設資金として街に入れる。M＝10万円で債券10万円なら1日300円分（月9,000円分）。利息は貯金額に数えない。債券がマイナスの間はつかない |
| RSV-03 | **備えLv**：債券残高が 0.5M / 1M / 2M / 3M でLv1〜4。Lvごとに防災倉庫・消防署・避難公園・銀行の金庫が建ち、備えの厚さが街の景色に出る |
| RSV-04 | 備えLvに応じて、悪い出来事の被害を軽くする（§10 EVT-04） |
| RSV-05 | 精算で債券が使い過ぎを肩代わりしたとき、「債券のおかげで、街の工事は止まりませんでした」と出す。債券がマイナスの間は利息も備えもなく、採掘の20%が強制的に債券へ回るので、工事が遅れる。この差を画面で見えるようにする |
| RSV-06 | 債券倍率 k（`BOND_MULTIPLIER_*`）は廃止する。債券の得は利息と備えにまとめる |

## 12. 試算

[game-balance-review.md](game-balance-review.md) とは別の、To-Be の簡易モデルで試算した。前提：M＝1、貯金は毎日均等、使い過ぎなし、債券は上限3Mまで自動、利息 0.3%/日、開拓期ボーナスは ERL-01 のとおり（上限は省略）、記録Lvボーナスは除く。

**発展Lvに届く日**（標準：毎月 0.2M ＋ 初日に 0.05M）

| 条件 | Lv2 | Lv3 | Lv4 | Lv5 | Lv6 |
|---|---:|---:|---:|---:|---:|
| 毎日記録する（To-Be） | 1日目 | 2日目 | 19日目 | 71日目 | 159日目 |
| 初日の入金なし | 3日目 | 10日目 | 33日目 | 84日目 | 171日目 |
| 記録しない（7日遅れで確定） | 8日目 | 9日目 | 26日目 | 78日目 | 166日目 |
| 開拓期ボーナス・利息なし | 1日目 | 11日目 | 38日目 | 98日目 | 218日目 |

**貯め方による違い**（毎日記録する）

| 貯め方 | Lv2 | Lv3 | Lv4 | Lv5 | Lv6 |
|---|---:|---:|---:|---:|---:|
| 控えめ：毎月 0.1M | 5日目 | 25日目 | 72日目 | 161日目 | 303日目 |
| 標準：毎月 0.2M ＋ 初日 0.05M | 1日目 | 2日目 | 19日目 | 71日目 | 159日目 |
| 積極：毎月 0.4M ＋ 初日 0.1M | 1日目 | 1日目 | 4日目 | 26日目 | 77日目 |

- E-2：初日の 0.05M で、町（Lv3）が10日目から2日目に、地方都市（Lv4）が33日目から19日目に早まる。
- E-3：開拓期ボーナスと利息で、Lv6 が218日目から159日目に早まる。1年間の利息は約1.4M 分になる。
- E-4：毎日記録すると、記録しない場合より Lv2 が1週間早く、Lv6 が1週間早い。
- 標準の貯め方での技術Lvは、Lv3 が16日目、Lv4 が38日目、Lv6 が143日目、Lv7 が293日目。Lv4 から Lv5 の間（約50日）は節目が少ないので、毎日の工事と出来事でつなぐ。

| 目標額 | 届く日 | M 基準だけ | 決定どおり（M/3 未満は目標額） | 案：M と目標額の小さいほう（Q7） |
|---:|---:|---|---|---|
| 0.1M | 8日目 | Lv3 | Lv6 | Lv6 |
| 0.2M | 23日目 | Lv4 | Lv6 | Lv6 |
| 0.32M | 41日目 | Lv4 | Lv5 | Lv5 |
| 0.34M | 44日目 | Lv4 | Lv4 | Lv5 |
| 0.5M | 68日目 | Lv4 | Lv4 | Lv5 |

決定どおりだと、目標が M/3 をわずかに下回る人（0.32M）は Lv5 で、わずかに上回る人（0.34M）は Lv4 で終わる。目標が小さいほうが大きな街で終わる逆転が起きる（Q7）。

| 債券倍率 k | 利息・備えLv（RSV-02・RSV-03・RSV-06） | `bond.ts`、`idle.ts` `advance` |
| 金貨→資源の交換（手数料5S）・おまかせの振り分け | 確定した貯金が自動で債券・建設資金に入る（RSV-01） | `ops.ts` `exchange`、`exchange.ts` `quoteNeedsExchange` |
| 銀貨→資源・都市資金の交換 | 修繕・装飾など（REC-06） | `exchange.ts`、`ops.ts` |

## 14. 設計原則との整合

| 原則（requirements.md 1.1） | To-Be での扱い |
|---|---|
| 1. 現実とゲーム内経済を区別する | 利息・建設資金はゲーム内だけのもの。換金できず、貯金額にも数えない |
| 2. 節約と継続を有利に | 街の育ち方は貯金（使わなかったお金）で決まる。記録の銀貨は金額に比例しない定額のまま |
| 3. 忘れても不当に損しない | 未記録の貯金は7日遅れで入るだけで減らない。開拓期ボーナスは採掘した日で判定。休業は72時間で自動再開。失うのは利息の数日分だけ |
| 4. 壊さない | 出来事は遅れと休業だけ。人口・建物は減らさない |
| 5. 支出を隠しても有利にならない | 自動確定では推定の支出を差し引く（REC-01）。正確に記録すれば、節約した分だけ多く入る |
| 6. 1つの目標で1つの物語 | 目標達成でエンディングは変えない。値段は基準額（M。目標額が M/3 未満なら目標額）で決まるので、小さな目標でも物語が短くなりすぎない（境目の扱いは Q7） |

README の「街は放っておいても自分で育つ」と requirements.md 4.2〜4.5・4.8 は、実装に合わせて書き換える。

## 16. 進め方

1. `scripts/balance.ts` を To-Be のモデル（貯金の流れ・確定・利息・開拓期ボーナス・出来事）で書き直し、§12 の表を実際の計画列で再現して κ（PRC-01）を決める。技術Lv7 の閾値を 1.5M に下げるか（Q5）もここで決める。
2. ゲームエンジン：GRW・PRC・ERL・RSV を `src/game` に入れる。放置計算は決定的なまま、ティックごとに「確定 → 債券・利息 → 計画の消化 → 出来事」の順に進める。
3. 記録：REC-01（確定と自動確定）、REC-02（今日は支出なし）、REC-05（自動受け取り）。
4. 悪い出来事：EVT-01〜EVT-06。
5. 画面と演出：FX-01〜FX-04、見通し（REC-04）、備えLv（RSV-03）。
6. requirements.md・README の改訂と、受入テストの追加。
