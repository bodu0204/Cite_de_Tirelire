# 必要資源の割合による交換 As-Is / To-Be

作成日：2026-10-19
関係：[requirements.md](requirements.md) 2.2・3.1・SCR-07、[bond-and-custom-currency.md](bond-and-custom-currency.md) §4（BND-05・BND-10）、[exchange.ts](../src/game/exchange.ts)、[ops.ts](../src/server/ops.ts) `exchange` / `exchangeToBond`、[sim.ts](../src/game/city/sim.ts) `plansFor` / `autoDevelop`、[exchange/page.tsx](../src/app/(game)/exchange/page.tsx)

## 1. 目的

次の2つを追加する。

- **おまかせ交換**：金貨を、都市がいま必要としている資源（木材・石材・食料）の割合に応じて自動で振り分けて交換できるようにする。資源の種類を選ばなくてよい。
- **債券への交換に資源をつける**：任意の通貨（金貨・ユーザ通貨）を債券に替えたとき、同じ額を「おまかせ交換」したのと同じ資源も街に入るようにする。ただし次の分は資源をつけない。
  - 債券がマイナスの間（0に戻すまで）に入る分
  - 債券が上限（月間自由予算 × 3）を超える分

## 2. 用語と前提

| 用語 | 定義 |
|---|---|
| 必要資源 | 都市がいま足りていない資源の量（木材・石材・食料）。§4.1 で定義する |
| 必要割合 | 必要資源を金貨に換算した額の比。おまかせ交換で金貨を振り分ける割合 |
| 債券上限 | 3M（M ＝ 月間自由予算 B。`bondCap`）。[bond-and-custom-currency.md](bond-and-custom-currency.md) §2 と同じ |
| 資源つき対象額 | 債券への交換額のうち、資源をつける分（§5.2） |

- 都市資金（treasury）は交換で得られない（requirements.md 2.2「都市資金↔金貨・銀貨 不可」）。必要資源に都市資金は含めない。
- ユーザ通貨は 1単位 ＝ 1円相当で金貨と同じ価値のため、資源への換算は金貨のレートを使う。

## 3. As-Is（現状）

### 3.1 資源交換（[ops.ts](../src/server/ops.ts) `exchange` の `to_resource`、[exchange.ts](../src/game/exchange.ts)）

- 金貨または銀貨を、**プレイヤーが選んだ1種類の資源**（木材・石材・食料）に交換する。
- レート：1G あたり 木材 10・石材 5・食料 10（`GOLD_RESOURCE_VALUE`）× (1 ＋ 銀行Lvボーナス ＋ 金鉱Lvボーナス)。銀貨は 1/10。
- 手数料：1回 5S（`FEE_EXCHANGE`）。
- 金貨で交換した額は見込み貯金に加える。
- 都市が何を必要としているかは画面に出ていない。プレイヤーが資源の状況を見て、種類ごとに何度も交換する必要がある（その都度 5S）。

### 3.2 債券への交換（`exchangeToBond`）

- 金貨・ユーザ通貨 → 債券 1:1、無料、上限を超えてもよい（BND-05）。
- 見込み貯金には加えない（BND-10）。
- **街には何も入らない**。債券は精算の肩代わりと債券倍率（時間発展の速度）にだけ効く。

### 3.3 都市の「必要」の扱い（[sim.ts](../src/game/city/sim.ts)）

- 自動開発は、方針の優先順（`policy.priorities`）に `plansFor` で候補の計画を並べ、最初に払える計画を始める。払えなくても 12時間以内に内部生産で貯まる見込みなら、下位の項目に回さずに待つ（`waitHours` ≤ `AUTO_MAX_WAIT_HOURS`）。
- 食料は住民の消費（`foodUse`）で毎ティック減る。在庫が 24時間分を切り、生産が消費の 1.05倍未満だと「不足」と判断し、農場を優先する。
- この「次に何が足りないか」は内部の判断にだけ使い、外には出していない。

## 4. To-Be：おまかせ交換（金貨 → 必要資源）

### 4.1 必要資源の定義

都市の今の状態（交換の直前に現在時刻まで再計算した状態）から、資源ごとに次の量を求める。

| 資源 | 必要量 |
|---|---|
| 木材・石材 | **自動開発が次に着手したい計画のコストの不足分**。方針の優先順に `plansFor` の候補を見て、最初に「今の在庫では払えない」計画を1つ選び、max(0, コスト − 在庫) とする |
| 食料 | **24時間分の不足分**。max(0, 消費 × 24 − (在庫 ＋ 生産 × 24)) |

- 自動開発が止まっている（`autoEnabled = false`）ときも、同じ手順で「次に着手したい計画」を求める（交換の目安として使うだけで、開発は始めない）。
- 必要量は資源の単位なので、**金貨に換算した額**（必要量 ÷ 1G あたりの交換量）で比べる。交換効率（Lvボーナス）は資源によらず同じ倍率なので、比には影響しない。

> 例：必要量 木材 300・石材 200・食料 100 のとき、金貨換算は 30G・40G・10G。必要割合は 木材 37.5%・石材 50%・食料 12.5%。

### 4.2 必要資源がないとき

すべての必要量が0（何も足りていない）のときは、**木材・石材・食料を金貨換算で均等（1/3ずつ）**に振り分ける。

> 「必要資源なしのため交換できない」にすると、債券への交換（§5）でも資源がつかなくなり、街が順調なほど損をするため。

### 4.3 交換の計算

| ID | 要件 |
|---|---|
| NX-01 | 金貨を必要割合で3つに振り分け、それぞれを §3.1 と同じレートで資源に替える。振り分けた金貨は整数にし、端数は最大剰余法で配る（合計は交換額と一致する） |
| NX-02 | 各資源の獲得量は切り捨て。振り分けが0Gの資源は獲得0 |
| NX-03 | 手数料は1回 5S（資源の種類が複数になっても1回分）。銀貨が足りなければ現行どおり失敗する（BND-11） |
| NX-04 | 必要量を上限にはしない（必要量より多く交換した分も同じ割合で入る）。割合は交換の直前に1回だけ求め、交換の途中で変えない |
| NX-05 | 金貨の交換額は現行どおり見込み貯金に加える |
| NX-06 | 銀貨のおまかせ交換は追加しない（金貨のみ。要望の範囲）。銀貨→資源は現行どおり種類を選ぶ |

> 例（Lvボーナスなし）：上の必要割合で 1,000G を交換 → 木材 375G → 3,750、石材 500G → 2,500、食料 125G → 1,250。手数料 5S。見込み貯金 +1,000。

## 5. To-Be：債券への交換に資源をつける

### 5.1 要件

| ID | 要件 |
|---|---|
| NX-11 | 金貨・ユーザ通貨を債券に替えたとき、債券には現行どおり交換額の全額が入る（1:1、無料。BND-05 は変えない） |
| NX-12 | あわせて、**資源つき対象額**（§5.2）を §4 のおまかせ交換と同じ割合・同じレートで資源に替えて街に入れる。交換元の通貨はそれ以上減らない（資源は債券化の「おまけ」） |
| NX-13 | この資源には手数料（銀貨）をかけない。銀貨0でも債券への交換はできる |
| NX-14 | この資源は見込み貯金に加えない（債券は達成率に直接含まれるため。BND-10 を維持） |
| NX-15 | 債券がマイナスの間に入る分（0に戻すまでの分）は資源をつけない |
| NX-16 | 交換後の債券が上限 3M を超えるとき、超えた分は資源をつけない。M ＝ 0 なら上限も 0 のため、資源はつかない |
| NX-17 | 対象は**プレイヤーが行う交換**（金貨→債券、ユーザ通貨→債券）だけ。採掘の自動債券化（BND-06・07）とユーザ通貨の余りの自動債券化には資源をつけない |

### 5.2 資源つき対象額

交換前の債券を b、交換額を a、上限を cap（＝ 3M）とすると、

```
資源つき対象額 ＝ max(0, min(b + a, cap) − max(b, 0))
```

つまり、交換で債券が動く区間 [b, b + a] のうち **[0, cap] に入る部分**だけに資源をつける。

| M | 交換前の債券 | 交換額 | 交換後の債券 | 資源つき対象額 | 理由 |
|---|---|---|---|---|---|
| 60,000 | 10,000 | 5,000 | 15,000 | 5,000 | 全額が 0〜180,000 の範囲 |
| 60,000 | −3,000 | 5,000 | 2,000 | 2,000 | −3,000〜0 の 3,000 は対象外 |
| 60,000 | −1,000 | 500 | −500 | 0 | マイナスのまま |
| 60,000 | 179,000 | 5,000 | 184,000 | 1,000 | 180,000 を超える 4,000 は対象外 |
| 60,000 | −2,000 | 200,000 | 198,000 | 180,000 | 0 未満の 2,000 と 180,000 超の 18,000 は対象外 |
| 60,000 | 200,000 | 5,000 | 205,000 | 0 | すでに上限を超えている |
| 0 | 0 | 5,000 | 5,000 | 0 | 上限 0 |

### 5.3 繰り返しの扱い

- 購入の精算で債券を使って減ったあと、再び債券に替えると、そのつど資源がつく（債券が減るのは現実の出費のためで、取り崩しを意図して繰り返すことはできない。債券 → 他の通貨は不可のまま）。
- 上限を超えた債券が精算で上限未満に下がったあと、交換で上限まで戻す分には資源がつく（§5.2 の式どおり）。

## 10. 決めておきたい点

本書では次のように仮に決めた。違う場合は指摘してほしい。

| # | 論点 | 本書の仮決め | 他の案 |
|---|---|---|---|
| Q1 | 「必要資源」の定義 | 自動開発が次に着手したい計画の不足分（木材・石材）＋ 食料の24時間不足分 | 直近24時間の消費量の比／方針プリセットごとの固定比 |
| Q2 | 必要資源がないとき | 均等に振り分ける | 交換不可にする／直近の建設で使った比にする |
| Q3 | 債券交換につく資源は「おまけ」か | おまけ（債券に全額入り、通貨はそれ以上減らない） | 交換額を債券と資源で分け合う（例：半分ずつ） |
| Q4 | 債券交換の資源に交換効率（銀行Lv・金鉱Lvのボーナス）を掛けるか | 掛ける（金貨のおまかせ交換と同じ量） | 掛けない（基本レートのみ） |
| Q5 | 自動債券化（採掘・ユーザ通貨の余り）にも資源をつけるか | つけない（プレイヤーの交換操作だけ） | つける |
| Q6 | おまかせ交換を銀貨にも用意するか | 用意しない | 銀貨でも選べるようにする |

> 補足（バランス）：Q3 をおまけにすると、上限までの範囲では「金貨→債券」が「金貨→資源」より常に得になる（債券も残り、資源も入る）。債券は現実の急な出費の備えであり、上限 3M と「債券→他の通貨は不可」で総量が抑えられるため、本書ではこれを許容した。金貨→資源は見込み貯金が増える点で差を残す。
