作成日：2026-10-19（2026-10-20 改訂：§10 の回答を反映。開発計画を無限に続くものとし、必要資源が0になる状態をなくした）
関係：[requirements.md](requirements.md) 2.2・3.1・SCR-07、[bond-and-custom-currency.md](bond-and-custom-currency.md) §4（BND-05〜07・BND-10）・§5.3・§7、[exchange.ts](../src/game/exchange.ts)、[ops.ts](../src/server/ops.ts) `exchange` / `exchangeToBond`、[sim.ts](../src/game/city/sim.ts) `plansFor` / `autoDevelop`、[idle.ts](../src/game/idle.ts) `advance`、[mine.ts](../src/game/mine.ts) `accrue`、[settle.ts](../src/game/settle.ts) `depositToBond`、[exchange/page.tsx](../src/app/(game)/exchange/page.tsx)

## 1. 目的

次の3つを追加する。

- **開発計画を無限に続ける**：都市の開発計画は尽きることがなく、常に「次に必要な資源」がある状態にする。必要資源が0になる状態はなくす。
- **おまかせ交換**：金貨・銀貨を、都市がいま必要としている資源（木材・石材・食料）の割合に応じて自動で振り分けて交換できるようにする。資源の種類を選ばなくてよい。
- **債券への交換に資源をつける**：任意の通貨（金貨・ユーザ通貨）が債券に入ったとき（プレイヤーの交換も、採掘・ユーザ通貨の余りの自動債券化も）、同じ量の金貨でおまかせ交換したのと同じ資源も街に入るようにする。ただし次の分は資源をつけない。
  - 債券がマイナスの間（0に戻すまで）に入る分
  - 債券が上限（月間自由予算 × 3）を超える分

## 2. 用語と前提

| 用語 | 定義 |
|---|---|
| 計画列 | 都市の開発計画を、着手したい順に並べたもの。具体的な計画のあとに拡張計画が無限に続く（§4.1） |
| 拡張計画 | 具体的な計画のあとに続く、終わりのない計画。資源の備蓄目標として必要資源の計算に使う（§4.1） |
| 必要資源 | 都市がいま足りていない資源の量（木材・石材・食料）。§4.2 で定義する。常に1つ以上が正 |
| 必要割合 | 必要資源を金貨に換算した額の比。おまかせ交換で振り分ける割合 |
| 債券上限 | 3M（M ＝ 月間自由予算 B。`bondCap`）。[bond-and-custom-currency.md](bond-and-custom-currency.md) §2 と同じ |
| 資源つき対象額 | 債券に入った額のうち、資源をつける分（§6.2） |

- 都市資金（treasury）は交換で得られない（requirements.md 2.2「都市資金↔金貨・銀貨 不可」）。必要資源に都市資金は含めない。
- ユーザ通貨は 1単位 ＝ 1円相当で金貨と同じ価値のため、資源への換算は金貨のレートを使う。

## 3. As-Is（現状）

### 3.1 資源交換（[ops.ts](../src/server/ops.ts) `exchange` の `to_resource`、[exchange.ts](../src/game/exchange.ts)）

- 金貨または銀貨を、**プレイヤーが選んだ1種類の資源**（木材・石材・食料）に交換する。
- レート：1G あたり 木材 10・石材 5・食料 10（`GOLD_RESOURCE_VALUE`）× (1 ＋ 銀行Lvボーナス ＋ 金鉱Lvボーナス)。銀貨は 1/10 × (1 ＋ 銀行Lvボーナス ＋ 銀鉱Lvボーナス)。
- 手数料：1回 5S（`FEE_EXCHANGE`）。銀貨払いなら代金の銀貨も必要。
- 金貨で交換した額は見込み貯金に加える。銀貨は加えない。
- 都市が何を必要としているかは画面に出ていない。プレイヤーが資源の状況を見て、種類ごとに何度も交換する必要がある（その都度 5S）。

### 3.2 債券への交換・自動債券化

- 金貨・ユーザ通貨 → 債券 1:1、無料、上限を超えてもよい（BND-05。`exchangeToBond`）。
- 採掘の一部は債券化率に応じて債券に入る。上限で止まり、マイナスの間は max(r, 20%)（BND-06・07。`accrue`）。
- 期限を迎えたユーザ通貨の余りは債券に入る。上限を超える分は金貨（§5.3。`depositToBond`）。
- 見込み貯金には加えない（BND-10）。
- **いずれも街には何も入らない**。債券は精算の肩代わりと債券倍率（時間発展の速度）にだけ効く。

### 3.3 都市の開発計画（[sim.ts](../src/game/city/sim.ts)）

- 自動開発は、方針の優先順（`policy.priorities`）に `plansFor` で候補の計画を並べ、最初に払える計画を始める。払えなくても 12時間以内に内部生産で貯まる見込みなら、下位の項目に回さずに待つ（`waitHours` ≤ `AUTO_MAX_WAIT_HOURS`）。
- 候補は、土地・解放条件・Lv上限・需要（空き家率など）で絞られるため、**候補が1件もないことがある**（計画が尽きる）。
- 食料は住民の消費（`foodUse`）で毎ティック減る。在庫が 24時間分を切り、生産が消費の 1.05倍未満だと「不足」と判断し、農場を優先する。
- この「次に何が足りないか」は内部の判断にだけ使い、外には出していない。

| NX-03 | 拡張計画は資源の備蓄目標で、それ自体は着工しない。土地・解放条件が揃って具体的な計画が出てきたら、計画列の先頭側に並び、自動開発（`autoDevelop`）が現行どおり着工する。自動開発の判断は変えない |

### 4.2 必要資源の定義

都市の今の状態（交換・債券化の時点まで再計算した状態）から、資源ごとに次の量を求める。

| 資源 | 必要量 |
|---|---|
| 木材・石材 | **計画列の不足分**。在庫を計画列の先頭から順に割り当て、最初に在庫が足りなくなった計画について max(0, コスト − 残りの在庫) とする |
| 食料 | **24時間分の不足分**。max(0, 消費 × 24 − (在庫 ＋ 生産 × 24)) |

- 拡張計画は無限に続くが、同じコストが並ぶので割り算で求められる（ループしない）。拡張計画に入った時点の残りの在庫を R、拡張計画1件のコストを c とすると、払える件数 k ＝ min（c > 0 の資源について ⌊R ÷ c⌋）、不足分 ＝ max(0, c − (R − k × c))。
- 自動開発が止まっている（`autoEnabled = false`）ときも、同じ計画列で求める（交換の目安として使うだけで、開発は始めない）。
- 必要量は資源の単位なので、**金貨に換算した額**（必要量 ÷ 1G あたりの交換量）で比べる。交換効率（Lvボーナス）は資源によらず同じ倍率なので、比には影響しない（銀貨でも同じ割合になる）。
- NX-02 により木材の必要量は常に正になりうるので、**必要資源がすべて0になる状態は存在しない**。

> 例1：計画列の不足分が木材 300・石材 200、食料の不足 100 のとき、金貨換算は 30G・40G・10G。必要割合は 木材 37.5%・石材 50%・食料 12.5%。
>
> 例2：具体的な計画がなく、拡張計画のコストが 木材 120・石材 260、在庫が 木材 500・石材 300・食料は十分のとき、払える件数 k ＝ min(⌊500÷120⌋, ⌊300÷260⌋) ＝ 1。不足分は 木材 max(0, 120 − 380) ＝ 0、石材 260 − 40 ＝ 220。必要割合は 石材 100%。

### 6.2 資源つき対象額

債券に入る前の債券を b、入る額を a、上限を cap（＝ 3M）とすると、

```
資源つき対象額 ＝ max(0, min(b + a, cap) − max(b, 0))
```

つまり、債券が動く区間 [b, b + a] のうち **[0, cap] に入る部分**だけに資源をつける。③④では、1ティックの中で債券に入った額ごとにこの式を使う。

| M | 入る前の債券 | 入る額 | 入った後の債券 | 資源つき対象額 | 理由 |
|---|---|---|---|---|---|
| 60,000 | 10,000 | 5,000 | 15,000 | 5,000 | 全額が 0〜180,000 の範囲 |
| 60,000 | −3,000 | 5,000 | 2,000 | 2,000 | −3,000〜0 の 3,000 は対象外 |
| 60,000 | −1,000 | 500 | −500 | 0 | マイナスのまま |
| 60,000 | 179,000 | 5,000 | 184,000 | 1,000 | 180,000 を超える 4,000 は対象外 |
| 60,000 | −2,000 | 200,000 | 198,000 | 180,000 | 0 未満の 2,000 と 180,000 超の 18,000 は対象外 |
| 60,000 | 200,000 | 5,000 | 205,000 | 0 | すでに上限を超えている |
| 0 | 0 | 5,000 | 5,000 | 0 | 上限 0 |

> ③採掘の債券化は上限で止まり、④余りの債券化は上限を超える分が金貨になるため、③④で上限超えの分が出ることはない。マイナスの間の強制債券化（BND-07）は、0に戻るまで資源がつかない。

### 6.3 繰り返しの扱い

- 購入の精算で債券を使って減ったあと、再び債券に入ると、そのつど資源がつく（債券が減るのは現実の出費のためで、取り崩しを意図して繰り返すことはできない。債券 → 他の通貨は不可のまま）。
- 上限を超えた債券が精算で上限未満に下がったあと、上限まで戻す分には資源がつく（§6.2 の式どおり）。

## 7. 放置計算への組み込み（[idle.ts](../src/game/idle.ts)）

- 現行の10分ティックの順序「金鉱（債券化含む）→ ユーザ通貨の発生・期限 → 街の1ティック」は変えない。
- ③④で債券に入った額は、同じティックの中で資源つき対象額を求め、**そのティック開始時の街の状態**の必要割合で資源にして、街の1ティックを進める前に在庫に加える。
- ティック境界は絶対時刻に揃っているので、7日を1回で計算しても1時間ごとに計算しても、同じティックで同じ量が入り、結果は一致する（AT-027 の原則を維持）。
- 獲得した資源はティックごとにまとめて台帳（イベント）に記録し、放置中の変化に「債券化で得た資源」として表示する。

| AT-034 | 銀貨 0 のとき、おまかせ交換は失敗する。金貨→債券は成功し、資源もつく |
| AT-035 | M ＝ 60,000：§6.2 の表の各行で、債券の増加は全額、資源つき対象額は表どおり。資源は同じ額の金貨でのおまかせ交換と同じ量（Lvボーナスを含む、手数料なし）。見込み貯金は増えない。ユーザ通貨→債券でも同じ |
| AT-036 | 債券化率 50%・債券 179,990・M ＝ 60,000：採掘の債券化で入った 10 の分だけ資源がつき、以後は債券化が止まるので資源もつかない。債券 −3,050・債券化率 0%：強制債券化（20%）で0に戻るまでは資源がつかず、0に達すると債券化が止まる（AT-017）ので、資源は一度もつかない。債券 −100・債券化率 50%：0に戻るまでの 100 は資源なし、それ以降の債券化分には資源がつく |
| AT-037 | 余りの債券化（AT-020 の食費コイン 5,000）で資源がつく。債券が上限で金貨になった分には資源がつかない。7日放置を1回で計算した結果と1時間ごとに計算した結果が一致する（債券化で得た資源を含む） |

## 12. 決定事項（2026-10-20）

| # | 論点 | 決定 |
|---|---|---|
| 追加 | 開発計画が尽きる場合 | 開発計画は無限に続く（拡張計画）。必要資源がない状態は存在しない（§4.1） |
| Q1 | 「必要資源」の定義 | 自動開発の計画（計画列）の不足分（木材・石材）＋ 食料の24時間不足分（§4.2） |
| Q2 | 必要資源がないとき | 必要資源がない状態は存在しない（計画列が無限に続くため） |
| Q3 | 債券に入った分につく資源は「おまけ」か | おまけ。債券に全額入り、通貨はそれ以上減らない。同じ量の金貨でのおまかせ交換と同じ資源がつく（NX-22・23） |
| Q4 | 交換効率（銀行Lv・金鉱Lvのボーナス）を掛けるか | 掛ける。金貨のおまかせ交換と同じ量（NX-23） |
| Q5 | 自動債券化（採掘・ユーザ通貨の余り）にも資源をつけるか | つける（NX-21 ③④、§7） |
| Q6 | おまかせ交換を銀貨にも用意するか | 銀貨でも選べる（NX-11） |

### 12.1 本書で決めた細部

| 論点 | 本書の決め方 |
|---|---|
| 拡張計画のコスト | 解放済みの新築のうち、木材＋石材の金貨換算が最も高いもの（NX-02）。街の成長に合わせて目標も上がる |
| 拡張計画を着工するか | しない。備蓄目標としてだけ使い、自動開発の判断は変えない（NX-03） |
| 自動債券化の資源の端数 | 切り捨てずに在庫に小数で加える（少額が毎ティック入るため、切り捨てると資源がほぼ入らなくなる） |

> 補足（バランス）：Q3・Q5 により、上限までの範囲では債券に入るお金がすべて資源も生む。債券化率を上げるほど、放置中にも資源が入り続ける。債券は現実の急な出費の備えであり、上限 3M と「債券→他の通貨は不可」で総量が抑えられるため、これを許容する。金貨→資源は見込み貯金が増える点で差を残す。
