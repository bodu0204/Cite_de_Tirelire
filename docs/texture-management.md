# テクスチャ管理 As-Is / To-Be

調査日：2026-10-15

## As-Is：画像のテクスチャは使っていない（ドットをすべてコードで描いている）

### 街のスプライト

[draw.ts](../src/components/city/draw.ts) にまとまっている。

- 1マス16×16ドットを `fillRect` で1つずつ塗っている（`p(x, y, w, h, "#色")`）。色の16進数は約170個で、すべてコードに直接書かれている。
- 建物は系統（line）と段階（tier）の `switch` で描き分けている（例：[drawHousing](../src/components/city/draw.ts#L93)）。全系統・全段階に絵があり、AT-014 の「外観変化」は満たしている。
- アニメーションは [CityCanvas.tsx](../src/components/city/CityCanvas.tsx#L21) が450msごとに `frame` を増やし、描画関数の中で座標をずらして表現している（煙・トラクター・発電所など）。
- 拡大は CSS の `image-rendering: pixelated` で行っている（[globals.css:92](../src/app/globals.css#L92)）。
- 描き直しは毎回全面。React が再描画するたびに、100マス分の `fillRect` を最初から実行している（[CityCanvas.tsx:25](../src/components/city/CityCanvas.tsx#L25)）。キャッシュはない。
- 別の画面からも使っている。[wishes/page.tsx:38](../src/app/(game)/wishes/page.tsx#L38) が `drawBuilding` を直接呼んで、像のプレビューを描いている。



### それ以外の見た目

- PWA アイコン：[make-icons.mjs](../scripts/make-icons.mjs) が文字で書いたドット絵とパレットから PNG を生成し、`public/icons/` に置いている。街のスプライトとは**描き方が別**。
- ナビのアイコンは絵文字（[AppShell.tsx:11](../src/components/AppShell.tsx#L11)）。



### 問題点

1. **建物の定義と絵の対応が暗黙。** `switch` の `default` が最上位の段階を兼ねている。そのため [catalog.ts](../src/game/catalog.ts) に段階を足すと、エラーにならず既存の絵で表示される。系統を足した場合も、`drawPublic` の最後の分岐に入り、何も言わずに「未来都市センター」の絵になる。
2. **絵を直すにはコードを触るしかない。** 色と形が関数の中に混在しているため、デザイナーや画像ツールでは編集できない。
3. **描画のたびに全部を描き直している。** 160px 四方なので今は問題ないが、演出を強化する FR-048 には向いていない。
4. **ドット絵の書き方が2種類ある。** 街は `fillRect` 命令、アイコンは文字のドット絵。



## To-Be：まだ決まっていない（提案）

要件定義には、テクスチャ管理の To-Be は書かれていない。関係する要件は、外観演出の FR-048（P1・2nd）と、像・公園のAIドット絵の FR-028（P2）だけ。以下は提案で、**2段階に分ける**。

### 段階1（いま着手できる・見た目は変えない）

- **絵を ID で引く台帳を作る。** `spriteKey(b)` を `"housing/3"` や `"special/bank@lv6"` のような文字列にし、`SPRITES[key]` から絵を取り出す形にする。`drawCity` はこの台帳を引くだけにする。
- **抜け漏れをテストで検出する。** catalog の全系統×全段階に絵があることを vitest で確かめ、`default` の分岐をなくす。
- **一度描いた絵を使い回す。** (key, アニメのコマ) ごとに OffscreenCanvas へ一度だけ描き、以後は `drawImage` で貼る。
- **（任意）書き方をそろえる。** 絵のデータを make-icons.mjs と同じ「文字のドット絵＋パレット」に移すと、1種類になる。



### 段階2（ FR-048 / FR-028 のとき）

- **画像ファイルに切り替える。** 台帳の中身を、PNG を1枚にまとめた画像（スプライトシート）と座標の JSON に替える。段階1で台帳を挟んでおけば、描画側は変えずに済む。
- **画像をオフラインでも出す。** [sw.js](../public/sw.js) は今、画面だけを先に保存している。画像のファイル名にバージョンを付け、先に保存する対象に加える。
- **AIドット絵は扱いを分ける。** ユーザーごとに作られる絵なので、上の画像ファイルとは別にサーバーへ保存し、建物IDから引くようにする。

まずは段階1の最初の2点（ID で引く台帳と、抜け漏れのテスト）だけでも価値がある。
